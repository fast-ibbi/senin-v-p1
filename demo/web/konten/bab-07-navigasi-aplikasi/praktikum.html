Praktikum Bab 7 — Aplikasi Manajemen Data Mahasiswa

Satu aplikasi utuh dari nol: pengarah awal, login, beranda dua tab, daftar lima mahasiswa, layar detail berparameter, dan form tambah/edit. Semua jalan pintas disengaja — data statis sebagai pengganti API (Bab 10), validasi ringkas (Bab 8), dan status masuk di memori (Bab 13). Yang dinilai hari ini adalah kerangka navigasinya.

Tujuan praktikum

Setelah menyelesaikan praktikum ini, kamu mampu:

  1. mengonfigurasi Expo Router pada project template blank: instalasi paket, perubahan main pada package.json, penambahan scheme, dan penghapusan App.js;
  2. membangun struktur folder app/ sesuai peta rute subbab 7.9: pengarah, login, dan grup (app) berisi tabs serta stack bersarang;
  3. mengimplementasikan perpindahan deklaratif (<Link>) dan imperatif (router) beserta pengiriman parameter;
  4. mengimplementasikan layar terlindungi dengan pola <Redirect /> berbasis status masuk sederhana;
  5. menguji seluruh alur: masuk → beranda → daftar → detail → tambah/edit → keluar.

Kebutuhan

  • Project Expo template blank bernama siakad-mobile (dibuat di Bab 2 dengan npx create-expo-app).
  • Node.js LTS minimal versi 22 dan aplikasi Expo Go pada ponsel, atau emulator Android (Bab 2).
  • Paket navigasi: expo-router, react-native-safe-area-context, react-native-screens, expo-linking, expo-constants, expo-status-bar, ditambah @expo/vector-icons untuk ikon tab.
  • Editor berkas yang dapat membuat folder baru — struktur project membutuhkan beberapa folder bersarang.

Persiapan

  1. Buat project baru berisi template blank. Jangan memakai template default, karena template itu berbasis TypeScript.
  2. Pasang paket navigasi sekaligus paket pendukungnya, lalu pasang ikon tab.
  3. Ubah nilai "main" pada package.json menjadi "expo-router/entry", lalu simpan. Nilai ini sensitif versi — periksa dokumentasi resmi untuk SDK yang terpasang.
  4. Tambahkan "scheme": "siakad-mobile" di dalam objek "expo" pada app.json, lalu simpan.
  5. Hapus berkas App.js. Berkas itu tidak lagi dimuat karena titik masuk sekarang milik Expo Router.
  6. Buat struktur folder di bawah ini. Folder baru harus dibuat lewat editor berkas atau perintah terminal, bukan dengan menyalin berkas.

Langkah kerja

  1. Siapkan data. Tulis data/mahasiswa.js berisi lima data mahasiswa baku buku ini dan fungsi pencarian berdasarkan id.
  2. Siapkan status masuk. Tulis lib/session.js berisi status login di memori dengan pola subscribe (daftar pendengar).
  3. Tulis layout akar (app/_layout.js): satu <Stack /> dengan dua layar bernama, yaitu login dan (app).
  4. Tulis pengarah (app/index.js): sudah masuk dialihkan ke /(app), belum masuk dialihkan ke /login.
  5. Tulis layar login (app/login.js): dua TextInput dan satu Pressable; saat ditekan, set status masuk lalu router.replace('/(app)').
  6. Tulis layout grup (app/(app)/_layout.js): periksa status masuk dengan <Redirect />; bila sudah masuk, tampilkan <Tabs /> berisi dua layar.
  7. Tulis Beranda (app/(app)/index.js): sapaan singkat, dua tautan, dan tombol Keluar.
  8. Tulis layout stack Mahasiswa (app/(app)/mahasiswa/_layout.js): tiga layar dengan judul masing-masing.
  9. Tulis Daftar Mahasiswa (app/(app)/mahasiswa/index.js): FlatList yang setiap kartunya dibungkus <Link asChild>.
  10. Tulis Detail Mahasiswa (app/(app)/mahasiswa/[id].js): baca id, cari data, tampilkan seluruh field, dan sediakan tautan Edit.
  11. Tulis Form Tambah/Edit (app/(app)/mahasiswa/tambah.js): baca parameter edit, isi nilai awal bila ada, ubah judul layar, lalu simpan dengan Alert dan router.back().
  12. Jalankan dan uji. Jalankan npx expo start, buka aplikasi di Expo Go, lalu telusuri seluruh alur pada bagian "Hasil yang diharapkan".

Penjelasan kode

data/mahasiswa.js memegang lima data baku yang sama persis dengan bab-bab lain. cariMahasiswa memanfaatkan find (Bab 3) untuk mencocokkan id, dan dipakai oleh layar Detail serta Form. Pada Bab 10, isi modul ini diganti oleh hasil fetch dari API — modul terpisah membuat penggantian itu hanya menyentuh satu berkas.

lib/session.js menyimpan status masuk di memori dengan tiga fungsi: membaca status (isLoggedIn), mengubahnya (setLoggedIn), dan mendaftarkan pendengar (subscribe). Pola subscribe inilah yang membuat layout (app) ikut ter-render ulang saat status berubah. Modul ini sengaja kecil: ia akan diganti Context di Bab 9 dan token sungguhan di Bab 13.

app/_layout.js adalah panggung seluruh aplikasi. Dua layar didaftarkan: grup (app) dengan header disembunyikan, dan login berjudul "Masuk". screenOptions memberi gaya seragam, sedangkan StatusBar mengatur warna bilah status sehingga tidak diulang di tiap layar.

app/index.js hanya bertugas mengarahkan: sudah masuk ke grup (app), belum masuk ke /login. Logika "ke mana pertama kali" yang terpusat di satu berkas membuat aplikasi mudah dipahami dan mudah diuji.

app/login.js sengaja disederhanakan: dua TextInput dan satu Pressable. Yang penting adalah alurnya, yaitu setLoggedIn(true) lalu router.replace('/(app)'). Perhatikan replace, bukan push: pengguna yang sudah masuk tidak boleh menekan kembali dan "mundur" ke layar login, karena replace mengganti layar login pada riwayat.

app/(app)/_layout.js adalah jantung layar terlindungi. Komponen membaca status masuk lewat useState yang diinisialisasi dari isLoggedIn, lalu berlangganan perubahan lewat useEffect(() => subscribe(setMasuk), []) — nilai balik subscribe berupa fungsi pembatalan, dan React memakainya sebagai pembersih efek. Jika belum masuk, layout mengembalikan <Redirect href="/login" /> sehingga konten tab tidak pernah terlihat. headerShown: false mencegah header ganda dengan stack Mahasiswa.

app/(app)/index.js memadukan dua pola dalam satu layar: <Link asChild> untuk tautan yang terlihat, dan router.replace('/login') di dalam fungsi keluar — perpindahan yang digerakkan logika setelah status dikosongkan. Gaya deklaratif dan imperatif memang hidup berdampingan sesuai perannya.

app/(app)/mahasiswa/_layout.js adalah stack kedua yang hanya berlaku untuk folder mahasiswa/. Dengan susunan ini tab Mahasiswa memiliki riwayat sendiri — Daftar, Detail, Form — dan tombol kembali perangkat bekerja alami di dalam stack.

app/(app)/mahasiswa/index.js memakai FlatList (Bab 5) dan membungkus setiap kartu dengan Link berbentuk objek: pathname menunjuk pola rute dinamis, params mengisi id. asChild memindahkan perilaku tautan ke Pressable sehingga seluruh kartu dapat ditekan, dan alamat layar menjadi /mahasiswa/2201001.

app/(app)/mahasiswa/[id].js membaca id lewat useLocalSearchParams dan menormalkannya dengan String(id). Bila data tidak ditemukan — misalnya alamat diketik manual dengan id yang salah — layar menampilkan pesan dan tautan kembali: pola empty state yang dibahas lebih dalam di Bab 10. Tautan "Edit Data ini" membawa parameter edit.

app/(app)/mahasiswa/tambah.js melayani dua mode lewat satu parameter. Tanpa edit ia mode tambah; dengan edit ia mode edit. useEffect dengan dependensi [edit] mengisi nilai awal dari data lama dan meresetnya saat mode berpindah. <Stack.Screen> di dalam komponen mengubah judul layar secara dinamis, lalu tombol simpan memeriksa kelengkapan isian, menampilkan Alert, dan memanggil router.back().

Hasil yang diharapkan

  1. Layar Masuk muncul pertama. Saat aplikasi dibuka, yang tampil adalah layar Masuk, karena index.js mengarahkan pengguna yang belum masuk ke /login.
  2. Masuk menuju Beranda. Isi email dan sandi apa pun, lalu tekan Masuk: aplikasi berpindah ke Beranda dengan bar dua tab di bawah, yaitu "Beranda" dan "Mahasiswa".
  3. Daftar berisi lima kartu. Tab Mahasiswa menampilkan Budi Santoso, Siti Aminah, Agus Wijaya, Dewi Lestari, dan Rizky Pratama, lengkap dengan NIM serta program studi.
  4. Detail terbuka dengan parameter benar. Menekan satu kartu membuka Detail dengan judul header "Detail Mahasiswa" dan seluruh field data; tombol kembali perangkat mengembalikan ke Daftar.
  5. Form mode edit terisi. Menekan "Edit Data ini" membuka form berjudul "Edit Mahasiswa" dengan isian nama, prodi, dan IPK yang sudah berisi data lama.
  6. Form mode tambah kosong. Dari Beranda, "Tambah Mahasiswa Baru" membuka form berjudul "Tambah Mahasiswa" dengan isian kosong; menekan tombol simpan saat semua kosong memunculkan Alert "Data belum lengkap".
  7. Keluar tidak bisa dibatalkan tombol kembali. Menekan Keluar mengembalikan ke layar Masuk, dan menekan tombol kembali pada saat itu tidak membuka Beranda — akibat pemakaian replace.
  8. Riwayat bertahan dalam sesi. Saat aplikasi dibuka ulang, kamu berada di layar terakhir yang dibuka, bukan di layar pertama.

Salah paham

Menghapus folder node_modules lalu memasang ulang bukan solusi untuk gejala di atas; itu hanya menghabiskan waktu praktikum. Ketiga gejala pertama berakar pada konfigurasi dan tipe data, bukan pada paket yang rusak. Kebiasaan yang sedang dilatih: baca pesan galat dan periksa berkas konfigurasi sebelum meminta bantuan.

Yang harus teramati

Catat empat hal berikut di lembar kerja praktikum.

  • Alur utuh — Login → Beranda → Daftar → Detail → Form berjalan tanpa layar kosong.
  • Riwayat tiap tab — posisi di tab Mahasiswa tidak hilang setelah berpindah ke Beranda.
  • Parameter terbaca — Detail menampilkan id yang benar, dan formulir terisi data lama saat mode edit.
  • Satu header — tidak ada dua bilah judul bertumpuk di layar mana pun.
Bukti yang bisa diperiksa lebih kuat daripada kesan: "tombol kembali di Detail membuka Daftar, bukan Login" dapat diuji ulang oleh orang lain; "navigasinya sudah jalan" tidak.

Kuis kilat

  1. Alamat apa yang dibuka berkas app/mahasiswa/[id].js?
  2. Apa peran nilai "main": "expo-router/entry" pada package.json?
  3. Mengapa layar tab membutuhkan useFocusEffect, bukan useEffect biasa?
  4. Mengapa layar login diletakkan di luar grup (app)?
Kunci kuis kilat
  1. /mahasiswa/<nilai> untuk nilai apa pun, misalnya /mahasiswa/2201001 — satu berkas melayani semua nilai segmen itu.
  2. Titik masuk aplikasi: berkas itu yang membuat navigation container, membaca folder app/, mendaftarkan semua rute, dan menyiapkan deep linking.
  3. Karena layar tab tetap terpasang di memori, efek sekali jalan tidak terpicu oleh fokus; useFocusEffect memantau fokus secara khusus.
  4. Supaya layar login tidak ikut terlindungi; kalau ikut, pengguna terlempar ke login berulang kali (redirect loop).

Ringkasan bab

  1. Navigasi mobile mengatur perpindahan layar, riwayat, dan data yang dilewatkan; pola utamanya stack (berjenjang), tab (sejajar), dan drawer (laci).
  2. Expo Router menerapkan file-based routing: setiap berkas di folder app/ menjadi satu rute, dan nama berkas menjadi alamatnya.
  3. Setup pada project blank memerlukan instalasi paket, perubahan "main" menjadi "expo-router/entry", dan penambahan "scheme" pada app.json.
  4. <Stack /> dan <Tabs /> membangun navigator; bedanya pada hierarki layar, kondisi layar yang tetap terpasang di tab, dan perilaku kembali.
  5. Navigasi deklaratif (<Link> dengan asChild) untuk tautan yang terlihat; imperatif (router.push, replace, back) untuk perpindahan yang digerakkan logika.
  6. Parameter dikirim lewat dynamic route ([id]) dan query parameter (?edit=...), dibaca dengan useLocalSearchParams, dan selalu bertipe string.
  7. Nested navigation diwujudkan dengan layout berlapis; folder (app) adalah grup rute yang tidak ikut dalam alamat.
  8. useFocusEffect dengan useCallback memicu proses setiap layar mendapat fokus — untuk penyegaran data, bukan pengganti useEffect pada proses sekali jalan.
  9. Layar terlindungi dilakukan pada satu titik, yaitu layout grup, dengan pola <Redirect href="/login" />; layar login harus berada di luar grup itu agar tidak terjadi redirect loop.
