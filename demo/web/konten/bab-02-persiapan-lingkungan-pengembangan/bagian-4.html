Empat Perintah dari Folder Kosong sampai Aplikasi Jalan

Alur pembuatan proyek boleh dibaca sebagai dua baris: menyiapkan, lalu menjalankan. Tidak ada langkah yang boleh dilewati — melewati pemeriksaan versi di awal adalah kebiasaan yang paling sering dan penyebab galat berantai di langkah sesudahnya. Empat perintah berikut dijalankan berurutan dari folder kerja.

Bacalah perintahnya, jangan dihafal. npx menjalankan versi terbaru create-expo-app tanpa memasangnya global; aplikasi-pertama adalah nama proyek sekaligus nama folder, sebaiknya huruf kecil tanpa spasi; --template blank memilih cetakan awal. Proses pembuatan memakan waktu satu sampai beberapa menit karena npm mengunduh setiap dependensi ke node_modules.

Lalu cd aplikasi-pertama memindahkan terminal ke folder proyek, dan code . meminta VS Code membuka folder yang sedang aktif. Kalau code . tidak dikenali, buka lewat menu File > Open Folder.

Pertanyaan penuntun

Kenapa setiap perintah berikutnya dijalankan dari dalam folder proyek? (Jawaban: npm dan Expo membaca package.json di folder yang sedang aktif; di luar folder itu mereka tidak menemukan apa pun.)

Subbab 2.7 · deck: “Kenapa Template blank, Bukan Template Bawaan?” · buku §2.7

Kenapa Template blank, Bukan Template Bawaan?

Ini keputusan penulisan buku, bukan sekadar selera. Templat blank berisi proyek React Native dan Expo minimal tanpa TypeScript — JavaScript polos, sesuai bahasa yang dipakai seluruh buku ini. Templat default yang dipakai create-expo-app tanpa opsi --template justru berbasis TypeScript dan langsung menyertakan Expo Router.

Akibat memilih templat bawaan: proyekmu berisi berkas berekstensi .tsx dan struktur navigasi yang belum dibutuhkan di tahap ini, sehingga kamu belajar dua hal sekaligus. Dengan memilih blank secara eksplisit, struktur proyek menjadi sesederhana mungkin dan perhatianmu tetap pada fondasi. Navigasi berbasis berkas baru dipelajari di Bab 7, dan alasan pemilihan JavaScript di Bab 3.

Salah paham

Perilaku templat dapat berubah antarversi Expo, jadi jangan menganggap susunan berkas hari ini berlaku selamanya. Bila ragu, periksa keterangan templat di docs.expo.dev atau jalankan npx create-expo-app --help sebelum membuat proyek untuk tugas.

Subbab 2.7 · deck: “Menjalankan Development Server dan Membaca Layarnya” · buku §2.7

Menjalankan Development Server dan Membaca Layarnya

Perintah ini menyalakan Metro Bundler lalu menampilkan antarmuka interaktif di terminal: kode QR untuk Expo Go, alamat jaringan tempat aplikasi disajikan, serta daftar tombol pintas. Jalankan dari dalam folder proyek.

  • a — membuka aplikasi di emulator Android
  • i — membuka di iOS Simulator (khusus macOS)
  • w — membuka versi web
  • r — memuat ulang aplikasi secara manual
  • Ctrl+C — menghentikan server pengembangan

Kamu juga dapat langsung menuju sasaran tertentu, misalnya npx expo start --android (setara menekan a) atau npx expo start --tunnel. Setelah server menyala, simpan perubahan pada App.js dan layar berubah dalam satu sampai dua detik — itulah Fast Refresh yang dibahas di bagian 2.

Salah paham

Jangan menutup terminal Expo selama praktikum. Menutupnya mematikan Metro, dan aplikasi di ponsel langsung kehilangan sambungan walaupun kodenya tidak berubah sama sekali.

Pertanyaan penuntun

Kenapa alamat exp:// penting bagi mahasiswa yang memakai ponsel? (Jawaban: itulah alamat tempat Metro menyajikan aplikasi, dan ponsel harus berada di jaringan yang sama dengan alamat itu.)

Subbab 2.8 · deck: “Isi Folder Proyek: Delapan Entri, Tiga yang Sering Disentuh” · buku §2.8

Isi Folder Proyek: Delapan Entri, Tiga yang Sering Disentuh

Buka folder aplikasi-pertama di VS Code dan cocokkan panel Explorer dengan struktur berikut — mencocokkan lebih berguna daripada menghafal.

Setelah npx expo start dijalankan, muncul satu entri tambahan yaitu folder .expo/ yang menyimpan pengaturan lokal dan informasi perangkat. Folder itu dibuat otomatis dan tidak perlu disentuh.

Salah paham

Isi persis templat bisa berbeda antarversi SDK — nama aset ikon, berkas tambahan seperti expo-env.d.ts, atau susunan app.json. Kalau strukturmu tidak sama persis dengan gambar di atas, itu normal. Yang wajib dipahami adalah peran empat berkas inti: App.js, index.js, app.json, dan package.json.

Subbab 2.8 · deck: “Peran File Inti: Identitas, Titik Masuk, Pendukung” · buku §2.8 & §Contoh 3

Peran File Inti: Identitas, Titik Masuk, Pendukung

Enam entri di folder proyek dapat dikelompokkan menjadi tiga fungsi: identitas proyek (app.json, package.json), titik masuk aplikasi (index.js, App.js), dan isi pendukung (assets/, node_modules/). Mengelompokkan seperti ini membuatmu tahu berkas mana yang boleh disentuh dan mana yang sebaiknya dibiarkan.

Peran berkas dan folder inti proyek Expo · sumber: deck “Peran File Inti”, buku §2.8
Berkas / folderPerannya
App.jsKomponen utama aplikasi — berkas yang paling sering kamu ubah
index.jsTitik masuk; memanggil registerRootComponent
app.jsonKonfigurasi proyek: nama, slug, versi, orientasi, ikon
package.jsonNama proyek, daftar skrip, dan dependensi versi pasti
assets/Aset statis: ikon aplikasi dan gambar bawaan templat
node_modules/Semua paket unduhan npm; tidak diedit dan tidak dilacak Git

app.json dibuat otomatis, tetapi beberapa kuncinya perlu kamu kenali sejak awal. Berikut inti yang wajib dipahami — bukan salinan persis templat, karena berkas hasil templat memuat lebih banyak kunci seperti ikon, splash screen, dan plugin.

name adalah nama yang tampil di bawah ikon pada ponsel; slug adalah identitas unik untuk layanan Expo; version adalah nomor versi aplikasimu, berbeda dari versi SDK; orientation membatasi orientasi layar; userInterfaceStyle mengatur tema; newArchEnabled menandakan proyek memakai New Architecture React Native. Konfigurasi inilah yang menjadi dasar saat build ke toko aplikasi di Bab 15.

Salah paham

Jangan mengedit package.json dengan tangan kecuali kamu memahami akibatnya. Daftar dependensi di dalamnya sudah disesuaikan dengan SDK; ubahlah lewat perintah npm install atau npx expo install, bukan lewat editor.

Subbab 2.8 · deck: “package.json Memanggil index.js, index.js Memanggil App.js” · buku §Contoh 2

package.json Memanggil index.js, index.js Memanggil App.js

Urutan pemanggilannya sederhana dan menjelaskan banyak hal: package.json menunjuk index.js melalui kunci main; index.js mendaftarkan App.js; App.js menggambar tampilan. Inilah sebabnya App.js menjadi berkas yang paling sering kamu ubah — ia titik masuk tampilan.

Baris pertama meminjam fungsi registerRootComponent dari paket expo, baris kedua mengimpor komponen App dari berkas App.js, dan baris terakhir menetapkan App sebagai komponen akar. Konsep import dan export dibahas tuntas di Bab 3; untuk sekarang cukup pahami alurnya: index.js → App.js → tampilan.

Salah paham

Karena App.js yang paling sering diubah, banyak yang menyimpulkan ia juga titik masuk proyek. Bukan begitu: yang didaftarkan di package.json adalah index.js. Menghapus atau mengganti nama berkas itu memutus rantai di atas walaupun kode tampilanmu benar.

Subbab 2.8–2.9 · deck: “Tiga Komponen Sudah Cukup untuk Layar Pertama” · buku §Praktikum (Kode)

Tiga Komponen Sudah Cukup untuk Layar Pertama

Aplikasi pertama yang kamu lihat bukan “Hello World” bawaan templat, melainkan versi ringkas yang kamu tulis sendiri. Tiga hal saja yang perlu ditunjukkan hari ini: dua baris import meminjam alat dari paket, View adalah kotak wadah (seperti div di web), dan Text adalah teks yang tampil.

View, Text, dan StyleSheet dibahas mendalam di Bab 5, jadi di sini cukup meniru polanya. Bagian yang boleh kamu ubah hari ini adalah isi teks di dalam Text — ganti dengan namamu, simpan, lalu amati Fast Refresh bekerja.

Salah paham

Kode di atas mengikuti pola resmi templat SDK 57, tetapi belum dijalankan di emulator oleh tim penyusun buku. Karena itu tanggung jawab mengujinya ada padamu: bila tampilannya berbeda dari yang kamu bayangkan, periksa dulu apakah galatnya di kode atau di lingkungan — praktikum di halaman berikutnya memandu urutan pemeriksaannya.
