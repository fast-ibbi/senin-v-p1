Subbab 2.4 · deck: “Expo CLI Dijalankan Lewat npx, Tanpa Pemasangan Global” · buku §2.4

Expo CLI Dijalankan Lewat npx, Tanpa Pemasangan Global

Expo adalah framework dan rantai alat yang menyederhanakan pengembangan React Native. Konsep dan cara kerjanya sudah kamu kenali di Bab 1; di sini kita fokus pada bagian yang kamu jalankan, yaitu Expo CLI — antarmuka baris perintah untuk membuat, menjalankan, dan mengelola proyek Expo.

Yang perlu ditegaskan: Expo CLI tidak perlu dipasang global. Semua perintahnya dijalankan lewat npx, sehingga tidak ada pemasangan yang harus diurus dan versi alatnya selalu segar dari registry. Tiga perintah berikut menutup hampir seluruh kebutuhan bab ini dan bab-bab berikutnya.

create-expo-app membuat proyek baru; expo start menyalakan server pengembangan; expo install menambah paket bawaan SDK dengan versi yang otomatis cocok. Perintah ketiga akan terasa manfaatnya jauh nanti, misalnya saat Bab 12 memakai kamera.

Pertanyaan penuntun

Nanti npx expo install dipakai untuk apa? (Jawaban: memasang paket bawaan SDK, misalnya kamera di Bab 12, supaya versinya otomatis cocok dengan SDK proyek.)

Subbab 2.4 · deck: “Expo Go Cepat, tetapi Tidak Semua Fitur Bisa Diuji” · buku §2.4

Expo Go Cepat, tetapi Tidak Semua Fitur Bisa Diuji

Expo Go adalah aplikasi yang dipasang di ponsel Android maupun iOS dan berfungsi sebagai “pemutar” proyek Expo. Selama ponsel dan komputer berada dalam jaringan Wi-Fi yang sama, aplikasi yang sedang kamu kembangkan langsung tampil di Expo Go tanpa proses build — dipindai lewat kode QR, selesai dalam hitungan detik.

Mengapa teknologi ini ada? Membangun aplikasi mobile secara tradisional membutuhkan build, yaitu penerjemahan kode menjadi berkas aplikasi, yang lambat dan rumit. Expo Go menghapus hambatan itu untuk tahap belajar. Analoginya: build tradisional seperti mencetak buku sebelum bisa dibaca, sedangkan Expo Go seperti membaca naskah langsung dari layar penulisnya.

Salah paham

Expo Go hanya mendukung API yang tersedia pada paket Expo dan tidak memuat kode native buatanmu sendiri. Untuk fitur khusus atau pengujian yang mendekati produksi, kamu perlu development build — topik Bab 15. Satu catatan lagi yang sensitif versi: karena SDK 57 baru dirilis, versi Expo Go di Google Play dan App Store bisa masih menunggu persetujuan, sehingga sementara waktu pemasangannya lewat eas go untuk iOS atau lewat fasilitas Expo CLI untuk Android sesuai petunjuk resmi docs.expo.dev.

Pertanyaan penuntun

Kapan Expo Go tidak lagi cukup? (Jawaban: saat aplikasi membutuhkan kode native sendiri atau pengujian yang mendekati produksi, sehingga perlu development build di Bab 15.)

Subbab 2.4 · deck: “Metro Membundel Kode, Perangkat Hanya Menerima Hasilnya” · buku §2.4

Metro Membundel Kode, Perangkat Hanya Menerima Hasilnya

Di balik layar, npx expo start menjalankan Metro Bundler — bundler JavaScript buatan Meta yang menjadi bawaan React Native. Metro membaca seluruh modul yang diimpor aplikasimu, menggabungkannya menjadi satu berkas, lalu mengirimkannya ke perangkat melalui jaringan pada port bawaan 8081.

Inilah sebabnya laptopmu menjadi “dapur” dan perangkat hanya menerima hidangan yang sudah matang. Alamat yang muncul di terminal, misalnya exp://192.168.x.x:8081, adalah alamat LAN tempat Metro menyajikan hasil olahannya — bukan alamat berkas di komputermu.

Pertanyaan penuntun

Kenapa perangkat tidak perlu tahu kode asli aplikasinya? (Jawaban: yang dikirim adalah bundle hasil kerja Metro, bukan berkas sumbernya; perangkat cukup menjalankan bundle itu.)

Subbab 2.4 · deck: “Menjalankan Development Server dan Membaca Layarnya” · buku §2.4

Fast Refresh: Simpan, dan Layar Mengikuti

Metro mendukung Fast Refresh: ketika kamu menyimpan perubahan pada berkas kode, aplikasi di layar diperbarui otomatis dalam sekejap tanpa kehilangan keadaan (state) yang sedang berjalan. Siklus “ubah–simpan–lihat” yang tadinya menuntut puluhan detik kini selesai dalam satu sampai dua detik, dan itulah pengalaman yang akan sangat terasa di Praktikum 2.

Tombol r di terminal Expo tetap ada gunanya: ia memuat ulang secara manual ketika Fast Refresh gagal diam-diam. Perhatikan terminal — Fast Refresh melaporkan statusnya di sana; bila layar tidak berubah, terminal biasanya sudah memberi tahu alasannya.

Tabel ini adalah rujukan, bukan bacaan berurutan. Boleh difoto, boleh ditempel di dekat meja kerja; yang penting kamu tahu fungsi tiap baris saat terminal menjawab sesuatu yang tidak kamu duga.

Pertanyaan penuntun

Kapan opsi --tunnel dipakai? (Jawaban: saat ponsel dan komputer tidak berada di satu jaringan, misalnya Wi-Fi kampus yang memblokir komunikasi antarperangkat — lihat bagian 3, subbab 2.9.)
