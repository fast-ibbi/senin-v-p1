Subbab 2.1 · deck: “Node.js Menjalankan JavaScript, Bukan Bahasa Baru” · buku §2.1

Node.js Menjalankan JavaScript, Bukan Bahasa Baru

Node.js adalah runtime — lingkungan eksekusi JavaScript yang berjalan di luar peramban. Sebelum Node.js lahir, JavaScript hanya dapat dieksekusi di dalam browser; tidak ada cara menjalankannya langsung di komputer. Node.js mengubah keadaan itu dengan membungkus mesin JavaScript V8 — mesin yang sama dengan browser Chrome — ke dalam sebuah program yang berjalan di sistem operasi.

Mengapa teknologi ini ada? Karena ekosistem pengembangan modern membutuhkan satu bahasa yang sama di banyak lapisan: bahasa yang kamu pakai menulis aplikasi mobile juga dipakai oleh alat-alat pengembangnya. Dengan begitu kamu tidak perlu mempelajari bahasa kedua hanya untuk memasang dependensi atau menyalakan server pengembangan. Bagi kita, Node.js adalah fondasi karena Expo CLI dan Metro Bundler berjalan di atasnya.

Berkas sekecil itu sudah cukup membuktikan bahwa Node.js benar-benar bisa menjalankan kode: console.log mencetak teks ke terminal, sedangkan process.version adalah properti Node.js yang menyimpan nomor versi runtime yang sedang berjalan. Jalankan dengan node sapaan.js; bila tiga baris teks muncul, rantai Node.js → npm → proyek berfungsi penuh.

Salah paham

Banyak mahasiswa mengira Node.js adalah bahasa pemrograman atau framework. Node.js tidak menambah sintaksis apa pun; ia hanya menyediakan tempat menjalankan. Kalimat “belajar Node.js” dalam percakapan sehari-hari sebenarnya berarti “belajar alat-alat yang berjalan di atas Node.js”.

Subbab 2.1 · deck: “npm Mencatat Daftar Paket, Bukan Menyimpannya Sendiri” · buku §2.1

npm Mencatat Daftar Paket, Bukan Menyimpannya Sendiri

npm (Node Package Manager — pengelola paket Node) adalah program yang terpasang otomatis bersama Node.js. Paket adalah pustaka kode siap pakai yang dibagikan melalui registry, yaitu gudang daring npmjs.com yang memuat jutaan paket. Tiga tugasnya berurutan: mengunduh paket dari registry, mengelola versinya, lalu mencatat daftarnya di berkas package.json dan menyimpan isinya di folder node_modules/.

Analoginya seperti perpustakaan yang mencatat setiap buku yang dipinjam: rak kerjamu bisa dibangun ulang kapan saja dari satu daftar. Catatan versi di package.json adalah sumber kebenaran; npm install adalah satu perintah yang membacanya; registry adalah toko daring tempat paket berasal — bukan folder di komputermu.

Salah paham

Istilah registry sering dibayangkan sebagai folder di komputer sendiri. Registry adalah gudang daring npmjs.com; yang ada di komputermu hanya node_modules/ — salinan hasil unduhan, bukan gudangnya.

Pertanyaan penuntun

Apa yang terjadi kalau folder node_modules/ dihapus? (Jawaban: cukup jalankan npm install dan seluruh paket terpasang kembali sesuai catatan package.json.)

Subbab 2.2 · deck: “Kapan Memakai npm install, Kapan npx?” · buku §2.2

Kapan Memakai npm install, Kapan npx?

Selain npm, kamu akan sering menjumpai npx — pelaksana paket yang ikut terpasang bersama npm. Bedanya satu kalimat: npm install <paket> memasang paket ke proyekmu, sedangkan npx <perintah> menjalankan perintah dari sebuah paket tanpa memasangnya secara permanen.

Mengapa npx ada? Karena alat seperti create-expo-app berubah seiring waktu. Dengan npx, kamu selalu menjalankan versi terbaru dari registry tanpa harus mengingat memperbarui instalasi global, dan tanpa membuat komputer penuh dengan program yang jarang dipakai. Karena itu seluruh perintah pembuatan proyek dan server pengembangan di buku ini memakai npx.

npm install meninggalkan jejak: namanya tercatat di package.json, isinya ada di node_modules/. npx tidak meninggalkan jejak permanen — yang tersisa hanya hasil kerjanya. Keduanya tidak saling menggantikan, dan keduanya akan kamu pakai di bab-bab berikutnya.

Salah paham

Dua kekeliruan yang paling mahal. Pertama, menganggap npx selalu lebih baik sehingga paket JavaScript murni pun dipasang lewat npx — padahal paket JavaScript murni dipasang dengan npm install, sedangkan paket bawaan SDK memakai npx expo install. Kedua, menuliskan nomor versi sendiri pada perintah pemasangan; biarkan npm memilih versi yang cocok dengan SDK.

Pertanyaan penuntun

Kenapa create-expo-app dijalankan dengan npx, bukan dipasang lebih dulu? (Jawaban: alat ini berubah dari waktu ke waktu, npx selalu mengambil versi terkini dan tidak menumpuk program yang jarang dipakai di komputer.)

Subbab 2.2 · deck: “Tiga Pengelola Paket, Satu Pilihan untuk Kelas Ini” · buku §2.2

Tiga Pengelola Paket, Satu Pilihan untuk Kelas Ini

Bayangkan aplikasi yang memakai sepuluh pustaka, dan setiap pustaka bergantung pada pustaka lain dengan versi tertentu. Mengelola hubungan semuanya secara manual akan cepat kacau — masalah yang dikenal sebagai dependency hell. Pengelola paket hadir untuk menjawab masalah nyata itu: mencatat daftar dependensi, mengunduh versi yang kompatibel, dan menyimpannya di node_modules/ sehingga proyek dapat dipasang ulang di komputer lain hanya dengan satu perintah.

Perbedaan utama di antara ketiganya bukan pada kemampuan, melainkan pada strategi penyimpanan berkas dan kecepatan. Trade-off-nya sederhana: npm kalah efisien di ruang disk dibanding pnpm, tetapi menang di kemudahan karena tidak perlu dipasang terpisah. Kelas ini konsisten memakai npm karena ia bawaan Node.js dan dipakai secara default oleh create-expo-app; konsistensi itulah yang menghindari kebingungan saat bekerja dalam tim.

Salah paham

Mencampur pengelola paket dalam satu tim bukan sekadar tidak rapi — ia menghasilkan berkas kunci yang berbeda antaranggota, sehingga “di laptopku jalan, di laptopmu tidak” menjadi sangat mungkin. Pilih satu pengelola, lalu tuliskan pilihan itu di dokumentasi tim.

Pertanyaan penuntun

Kalau ada tiga pilihan, mana yang paling aman untuk kerja tim di kelas? (Jawaban: npm, karena ikut terpasang bersama Node.js dan dipakai bawaan oleh create-expo-app sehingga beda lockfile antaranggota tidak terjadi.)

Subbab 2.3 · deck: “VS Code: Menulis, Menjalankan, dan Membaca Error” · buku §2.3

VS Code: Menulis, Menjalankan, dan Membaca Error

Visual Studio Code adalah editor kode sumber gratis buatan Microsoft, dan editor paling populer untuk pengembangan JavaScript. Alasan keberadaannya bukan selera: satu proyek React Native berisi puluhan hingga ribuan berkas, sehingga menulisnya di editor teks polos tidak realistis. VS Code menyediakan penyorotan sintaks, pelengkapan kode otomatis (IntelliSense), penelusuran lintas berkas, dan terminal terintegrasi — terminal di dalam editor, sehingga kamu tidak perlu berpindah aplikasi saat menjalankan perintah.

Kekuatan VS Code bertumpu pada ekstensi. Untuk React Native dan Expo, empat ekstensi ini cukup: ESLint memeriksa kualitas kode dan menandai kesalahan gaya penulisan; Prettier merapikan format kode otomatis saat berkas disimpan; Error Lens menampilkan pesan kesalahan tepat di samping baris yang bermasalah; Material Icon Theme memberi ikon berwarna dan bersifat opsional, murni kenyamanan visual.

Perintah code . menyuruh VS Code membuka folder saat ini; tanda titik berarti direktori aktif. Jika perintah itu tidak dikenali, buka VS Code lewat menu Start atau Launchpad, lalu pilih File > Open Folder dan arahkan ke folder proyek.

Salah paham

Daftar ekstensi bersifat sensitif versi. Sebagian ekstensi di marketplace berhenti dirawat dan diarsipkan pembuatnya — termasuk yang pernah populer seperti React Native Tools. Periksa nama ekstensinya di marketplace sebelum memasang, dan ingat bahwa kombinasi ESLint + Prettier + terminal Expo sudah mencukupi untuk seluruh buku ini.

Pertanyaan penuntun

Kenapa Prettier penting dalam kerja tim? (Jawaban: format kode semua anggota menjadi seragam, sehingga perubahan di Git lebih mudah dibaca dan ditinjau.)

Subbab 2.1 · deck: “Dua Perintah yang Membuktikan Lingkunganmu Siap” & “Kalau Perintahnya Tidak Dikenali, Masalahnya di PATH” · buku §2.1

Dua Perintah yang Membuktikan Lingkunganmu Siap

Cara memverifikasi bahwa Node.js dan npm telah terpasang adalah memeriksa versinya. Buka terminal — PowerShell atau Command Prompt di Windows, Terminal di macOS dan Linux — lalu jalankan dua perintah berikut. Kalau keduanya mencetak nomor versi, lingkunganmu siap.

Buku ini memakai Node.js LTS (Long Term Support — dukungan jangka panjang) versi minimal 22. LTS berarti versi itu dipelihara dan diperbarui keamanannya dalam waktu lama, sehingga paling stabil untuk pengembangan. Pilih label LTS, bukan Current. Angka LTS terbaru berubah seiring waktu; gunakan rilis LTS terbaru dari situs resmi nodejs.org.

Jika terminal menjawab node: command not found atau 'node' is not recognized, berarti Node.js belum terpasang atau belum dikenali. PATH adalah daftar folder tempat sistem operasi mencari perintah — bayangkan sebagai buku alamat milik terminal. Masalah paling sering bukan pemasangan, melainkan terminal lama yang belum memuat PATH yang baru.

Salah paham

Memasang ulang Node.js berkali-kali padahal cukup membuka terminal baru adalah kebiasaan paling sering di kelas. Terminal yang lama masih memakai daftar PATH lama; terminal baru membaca PATH yang sudah diperbarui.

Pertanyaan penuntun

Kenapa menutup lalu membuka terminal bisa memperbaikinya? (Jawaban: terminal baru membaca PATH yang sudah diperbarui, sedangkan terminal lama masih memakai daftar lama yang dibaca saat ia dijalankan.)
