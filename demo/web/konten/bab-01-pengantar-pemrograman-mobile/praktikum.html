Praktikum Bab 1 — Lingkungan & Observasi

Tiga pekerjaan: memasang dan memverifikasi lingkungan pengembangan, menjalankan script pemeriksa, lalu menyusun laporan observasi tiga aplikasi mobile. Belum ada kode aplikasi di sini — dan itu disengaja.

Tujuan praktikum

Setelah menyelesaikan praktikum ini, kamu mampu:

  1. menginstal Node.js LTS dan memverifikasi pemasangannya bersama npm;
  2. memasang Visual Studio Code sebagai editor kode;
  3. membuat akun Expo sebagai syarat menggunakan layanan pengembangan;
  4. menjalankan script pemeriksaan lingkungan dan membaca hasilnya;
  5. mengamati tiga aplikasi mobile yang dipakai sehari-hari dan menyusun laporan observasi.

Kebutuhan

  • Komputer (Windows 10/11, macOS, atau Linux) dengan hak untuk memasang perangkat lunak.
  • Koneksi internet yang stabil (untuk mengunduh penginstal dan mendaftar akun).
  • Alamat email yang aktif (untuk pendaftaran akun Expo).
  • Smartphone dengan minimal tiga aplikasi mobile yang sering kamu gunakan (objek observasi).
  • Editor teks bawaan sudah cukup, tetapi disarankan langsung memasang Visual Studio Code.

Persiapan

  1. Tutup aplikasi berat yang tidak perlu agar proses instalasi berjalan lancar.
  2. Catat versi sistem operasi dan arsitektur prosesor (64-bit) — penginstal Node.js tersedia sesuai sistem.
  3. Siapkan akses administrator. Jika memakai komputer laboratorium kampus yang terkunci, koordinasikan dengan pengelola lab.
  4. Pastikan mengunduh LTS (Long Term Support), bukan versi “Current” — LTS adalah pilihan stabil dan sesuai asumsi versi buku (Node.js minimal 22).
  5. Siapkan buku catatan untuk mencatat kendala — mencatat masalah adalah bagian dari kebiasaan profesional yang dibangun buku ini.

Langkah kerja

  1. Unduh Node.js LTS dari nodejs.org. Alur situs unduhan dapat berubah; pastikan memilih label “LTS”, bukan “Current”.
  2. Instal Node.js dengan seluruh opsi bawaan. Proses selesai setelah muncul layar “Completed”.
  3. Buka terminal baru. Tutup terminal yang sudah terbuka sebelumnya — terminal baru diperlukan agar sistem mengenali perintah Node.js yang baru dipasang.
  4. Verifikasi instalasi: jalankan node --version lalu npm --version. Jika keduanya menampilkan nomor versi, instalasi berhasil.
  5. Instal Visual Studio Code dengan opsi bawaan — editor yang dipakai seluruh buku ini karena ringan, mendukung JavaScript dengan baik, dan punya terminal terintegrasi.
  6. Buat akun Expo di expo.dev. Akun ini dipakai mulai Bab 2 untuk menjalankan project dengan Expo.
  7. Jalankan script pemeriksaan lingkungan. Buat folder kerja misalnya latihan-bab1, buat berkas cek-lingkungan.js dengan isi persis seperti di bawah, lalu jalankan dari terminal.
  8. Buat laporan observasi. Pilih tiga aplikasi mobile yang benar-benar kamu gunakan dalam seminggu terakhir; jalankan juga profil-aplikasi.js dengan data pilihanmu, lalu sertakan keluarannya di laporan.

Penjelasan kode

cek-lingkungan.js adalah program Node.js paling sederhana yang berguna sungguhan. require('node:child_process') mengimpor modul bawaan Node.js yang mampu menjalankan perintah sistem; const {'{'} execSync {'}'} = … mengambil satu fungsi dari modul itu — “Sync” berarti pemanggilan berjalan sinkron (menunggu perintah selesai sebelum melanjutkan). Fungsi ambilVersi dibungkus try/catch sehingga kegagalan (perintah tidak dikenal) tidak menghentikan program, melainkan mengembalikan null; inilah pola penanganan kesalahan yang akan dipelajari lebih dalam di Bab 3.

Operator ?? memastikan nilai null ditampilkan sebagai “TIDAK TERPASANG” — cara ringkas menulis nilai cadangan. Bagian penilaian memakai versiNode.match(/^v(\d+)/) untuk menangkap angka utama versi (misalnya 22 dari v22.14.0), lalu membandingkannya dengan ambang 22. Tiga cabang if/else mencetak kesimpulan sesuai kondisi. Logika “periksa → bandingkan → simpulkan” ini adalah cermin mini cara kerja aplikasi yang lebih besar.

profil-aplikasi.js mendefinisikan satu array berisi tiga objek; setiap objek mewakili satu aplikasi dengan atribut nama, kategori, platform, perkiraan jenis, fitur perangkat, dan penilaian. Perulangan for...of menelusuri array dan mencetak setiap atribut, dengan join menggabungkan array teks menjadi satu kalimat dipisah koma. Isi data di sini hanyalah contoh — tugasmu adalah mengganti ketiganya dengan aplikasi yang benar-benar kamu gunakan.

Hasil yang diharapkan

  1. Terminal: node --version menampilkan nomor versi LTS (diawali v, misalnya v22.x.x) dan npm --version menampilkan nomor versi npm — bukan pesan kesalahan.
  2. Keluaran script menyerupai contoh di bawah (angka versi di komputer kamu dapat berbeda).
  3. Akun Expo: pendaftaran berhasil ditandai dengan email konfirmasi dan kamu dapat masuk ke situs Expo.
  4. Laporan observasi: satu berkas berisi tiga aplikasi yang diamati lengkap dengan kategori, perkiraan jenis, fitur perangkat, penilaian, beserta kesimpulan.

Salah paham

Kegagalan lingkungan bukan kegagalan logika. Dua jam pertama praktikum sering habis untuk masalah PATH, bukan untuk materi. Selesaikan dulu Troubleshooting sebelum menduga-duga soal kode — dan jangan memasang ulang semuanya berkali-kali tanpa membaca pesan errornya.

Yang harus teramati

  • Versi yang tepat — Node.js LTS minimal 22, bukan versi “Current”.
  • Bukti, bukan kesan — sertakan tangkapan layar keluaran cek-lingkungan.js dan profil-aplikasi.js.
  • Alasan di laporan — setiap aplikasi diberi perkiraan jenis beserta alasan yang bisa diperiksa (dipasang dari toko aplikasi? memakai kamera/GPS? notifikasi bekerja?).
Laporan yang baik menjawab “mengapa kamu menyimpulkan aplikasi itu native”, bukan hanya “aplikasi itu native”.

Kuis kilat

  1. Sebutkan tiga dari tujuh karakteristik aplikasi mobile dan satu keputusan desain yang lahir darinya.
  2. Apa perbedaan mendasar hybrid dan cross-platform modern?
  3. Apa peran Expo Go pada praktikum Bab 2 nanti?
  4. Sebutkan tiga lapisan arsitektur klien dan satu bab tempat masing-masing dilatih.
Kunci kuis kilat
  1. Contoh: mobilitas → sesi pendek dan penyimpanan keadaan; sentuhan → target sentuh besar; sensor → kamera/GPS sebagai nilai utama; sumber daya terbatas → kode hemat.
  2. Hybrid merender halaman web di dalam WebView; cross-platform modern merender komponen UI native milik sistem operasi.
  3. Menjalankan project Expo langsung di ponsel lewat pemindaian kode QR, tanpa membangun aplikasi native atau memasang Android Studio/Xcode.
  4. Presentasi (Bab 5–7), bisnis (Bab 8–9, 14), data (Bab 10–11, 13).

Ringkasan bab

  1. Aplikasi mobile berbeda dari website bukan karena layarnya kecil, melainkan karena konteks, sentuhan, sensor, konektivitas, distribusi, sumber daya, dan siklus hidupnya.
  2. Ada empat pendekatan: native, web mobile, hybrid, dan cross-platform; masing-masing adalah pertukaran biaya, performa, dan pengalaman pengguna.
  3. Android menang pada jangkauan dan keterbukaan dengan harga fragmentasi; iOS menang pada konsistensi dengan harga ketertutupan dan biaya.
  4. Setiap era teknologi mobile lahir sebagai jawaban atas keterbatasan era sebelumnya; React Native adalah jawaban atas mahalnya dua codebase native.
  5. React Native menulis sekali dengan JavaScript dan menggambar dengan komponen native; Expo merapikan pekerjaan konfigurasi di atasnya.
  6. Arsitektur klien–server dengan tiga lapisan (presentasi, bisnis, data) adalah kerangka seluruh buku ini.
