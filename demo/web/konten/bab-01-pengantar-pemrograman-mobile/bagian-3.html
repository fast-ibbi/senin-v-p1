Subbab 1.5–1.7. Bagian ini menjawab tiga pertanyaan berurutan: bagaimana React Native bekerja, apa peran Expo di atasnya, dan kapan pilihan itu tepat — lengkap dengan harga yang harus dibayar.

Subbab 1.5 · deck: “Ditulis Sekali, Digambar Native di Dua Platform” · buku §1.5

Ditulis Sekali, Digambar Native di Dua Platform

React Native (disingkat RN) adalah framework sumber terbuka yang dikembangkan Meta untuk membangun aplikasi Android dan iOS menggunakan JavaScript — bahasa yang sama dengan web. Ia turunan dari pustaka React untuk antarmuka web; pola pikirnya (component, props, state — lihat Bab 4) dibawa utuh ke dunia mobile, tetapi elemen antarmukanya berubah dari tag HTML menjadi komponen khusus mobile.

Konsep intinya sederhana namun revolusioner: tulis antarmuka sekali dengan JavaScript, dan React Native akan menggambar antarmuka itu menggunakan komponen UI native milik masing-masing platform. Ketika kamu menulis komponen View (wadah tata letak), di Android ia menjadi ViewGroup dan di iOS menjadi UIView — bukan kotak abu-abu di dalam halaman web, melainkan elemen antarmuka sungguhan milik sistem operasi.

Subbab 1.5 · deck: “JavaScript Memerintah, Native yang Menggambar” · buku §1.5

JavaScript Memerintah, Native yang Menggambar

Di dalam aplikasi React Native terdapat dua “dunia” yang hidup bersamaan: dunia JavaScript tempat logika aplikasi berjalan (dijalankan mesin JavaScript bernama Hermes yang dioptimalkan untuk perangkat mobile), dan dunia native tempat antarmuka digambar. Kedua dunia berkomunikasi melalui lapisan penghubung yang meneruskan pesan bolak-balik: JavaScript memerintahkan “buat tombol hijau di sini”, lapisan native menerjemahkannya menjadi tombol asli, lalu melaporkan kejadian seperti ketukan pengguna kembali ke JavaScript.

Selain antarmuka native, React Native mewarisi keunggulan pengembangan dari ekosistem web: hot reload (perubahan kode langsung terlihat tanpa membangun ulang aplikasi), pembaruan cepat, dan akses ke jutaan pustaka npm. Saat aplikasi dijalankan dalam mode pengembangan, bundler bernama Metro menggabungkan seluruh berkas JavaScript menjadi satu dan mengirimkannya ke perangkat — inilah yang akan kamu lihat berjalan saat npx expo start di Bab 2.

Salah paham

Lapisan penghubung sering disebut “bridge” dan dianggap selamanya lambat. Sebenarnya arsitekturnya terus disempurnakan dengan renderer dan mekanisme komunikasi yang lebih cepat. Detail arsitektur React Native terkini sebaiknya diverifikasi di dokumentasi resmi reactnative.dev, karena terus diperbarui.

Subbab 1.5 · deck: “React Native Bukan Penerjemah Kode” · buku §1.5

React Native Bukan Penerjemah Kode

Perlu ditegaskan apa yang bukan React Native: ia bukan penerjemah kode ke bahasa native (Kotlin/Swift) dan bukan pembungkus halaman web. Kode JavaScript tetap berjalan sebagai JavaScript; yang “native” adalah tampilan antarmukanya.

Konsekuensinya penting untuk memilih teknologi: aplikasi React Native unggul untuk aplikasi berbasis data (form, daftar, integrasi server) — bukan untuk permainan ber-grafik berat yang tetap lebih baik ditulis native.

Subbab 1.6 · deck: “Expo: Tiga Komponen Utama” · buku §1.6

Expo: Tiga Komponen Utama

React Native menyelesaikan masalah “dua codebase”, tetapi meninggalkan pekerjaan rumah lain: membangun dan mengonfigurasi project native (Xcode/Android Studio), menangani modul perangkat, dan membangun berkas rilis. Expo adalah framework di atas React Native yang merapikan pekerjaan rumah itu. Jika React Native adalah “bahasa dan mesin”, Expo adalah “lingkungan kerja yang membuat mesin itu mudah dipakai”.

  1. Expo SDK — kumpulan pustaka resmi yang menyatukan akses ke fitur perangkat (kamera, lokasi, notifikasi, penyimpanan) dengan API yang konsisten lintas platform. Buku ini memakai Expo SDK 57.
  2. Expo Go — aplikasi perangkat yang memungkinkan project Expo dijalankan langsung di ponsel tanpa membangun aplikasi native sama sekali. Ketik npx expo start, pindai kode QR, aplikasi tampil — proses yang ideal untuk belajar karena menghilangkan hambatan instalasi Android Studio atau Xcode di tahap awal.
  3. EAS (Expo Application Services) — layanan cloud untuk membangun dan menerbitkan aplikasi ke toko aplikasi, termasuk menghasilkan berkas APK/AAB untuk Android. EAS dipakai di Bab 15.

Subbab 1.6 · deck: “Setiap Kemudahan Expo Punya Harganya” · buku §1.6

Setiap Kemudahan Expo Punya Harganya

Bagi mahasiswa, manfaat terbesar Expo adalah kurva belajar: dari nol hingga aplikasi berjalan di ponsel hanya butuh beberapa langkah — pengalaman pertama yang menyenangkan, bukan frustrasi konfigurasi. Tentu ada harga yang dibayar, dan kamu berhak mengetahuinya sejak awal.

  • Aplikasi Expo cenderung lebih besar ukurannya.
  • Jika project membutuhkan modul native yang belum didukung Expo, kamu harus keluar dari jalur nyaman dan melakukan prebuild atau development build — pekerjaan yang lebih rumit, dibahas konseptual di Bab 15.
  • Fitur perangkat mutakhir kadang baru tersedia setelah tim Expo menyesuaikannya ke SDK terbaru, sehingga ada jeda antara rilis fitur native dan dukungan Expo.

Bagi mayoritas aplikasi sistem informasi, ketiga keterbatasan ini tidak menghalangi; bagi project khusus, inilah pertimbangan trade-off yang harus dievaluasi.

Subbab 1.7 · deck: “Keunggulan dan Keterbatasan React Native” & “Kapan React Native Tepat Dipakai?” · buku §1.7

Keunggulan dan Keterbatasan React Native

Keputusan memilih React Native tidak boleh didasarkan pada tren, melainkan pada analisis keunggulan dan keterbatasannya — itulah esensi analisis pertukaran yang menjadi ciri berpikir profesional.

Keunggulan dan keterbatasan React Native · sumber: buku §1.7, Tabel 1.3
KeunggulanKeterbatasan
Satu basis kode untuk Android dan iOSPerforma di bawah native untuk beban ekstrem
Tim JavaScript dapat langsung produktifAplikasi lebih besar dan lebih boros memori
Ekosistem npm yang sangat luasFitur platform terbaru kadang terlambat diadopsi
Hot reload mempercepat iterasiDebugging lintas lapisan (JS + native) lebih rumit
Pembaruan aplikasi tanpa membangun ulangModul native khusus tetap butuh keahlian native
Komunitas besar dan banyak materi belajarBergantung pada kestabilan versi pustaka pihak ketiga

Mari bedah tiap sisi. Keunggulan: penghematan terbesar dari satu basis kode justru terjadi pada pemeliharaan jangka panjang, bukan pada penulisan awal; kesinambungan keterampilan berarti tim yang menguasai JavaScript bisa langsung membangun antarmuka native; ekosistem npm dan komunitas besar mempercepat penyelesaian masalah; hot reload menghasilkan siklus “ubah–lihat hasil” yang pendek dan sangat mendukung belajar; pembaruan kecil bisa dikirim tanpa peninjauan ulang toko; dan tenaga kerja dengan keterampilan React Native relatif mudah ditemukan.

Keterbatasan: aplikasi yang menuntut rendering grafis real-time kelas berat (game 3D, editor video) tetap lebih baik native; aplikasi membawa runtime JavaScript sehingga berkasnya lebih besar dan konsumsi memorinya lebih tinggi; ketika Apple atau Google merilis fitur baru, perlu waktu sebelum React Native mendukungnya; kesalahan bisa terjadi di lapisan JavaScript, lapisan native, atau keduanya (Bab 14 melatih penelusurannya); dan modul native yang sangat khusus tetap menuntut keahlian Kotlin/Swift.

Kapan tepat dipakai? Pola umumnya: aplikasi yang kaya antarmuka dan data tetapi tidak menuntut performa ekstrem — aplikasi bisnis, e-commerce, layanan, sistem informasi — justru mendapat manfaat terbesar, karena kecepatan pengembangan lebih penting daripada keunggulan performa marginal. Inilah profil mayoritas aplikasi di dunia nyata, dan inilah alasan buku ini memilih React Native.
