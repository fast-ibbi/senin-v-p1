Bab 10 — REST API dan Backend Integration

Dari data statis ke data di server · Pertemuan 10–11 · Sub-CPMK 5.1 & 5.2. Sembilan pertemuan pertama memakai data yang kamu ketik sendiri di dalam kode; bab ini memindahkan data itu ke mesin lain dan mengajari aplikasi memintanya dengan sopan — arsitektur client–server, HTTP, REST, JSON, metode GET/POST/PUT/PATCH/DELETE, status code, fetch, tiga state antarmuka, base URL, pemisahan api/ dan screens/, serta pengantar autentikasi API.

Pertanyaan pembuka deck: “Siapa yang pernah melihat pesan gagal memuat data di aplikasi dan tidak tahu harus berbuat apa?”

Tampung jawaban tanpa dikoreksi dulu. Bandingkan lagi di akhir pertemuan, saat tiga state antarmuka dibahas di bagian 4.

Tujuan pembelajaran

Setelah bab ini, kamu bisa:

  • Menjelaskan arsitektur client–server dan peran API di dalamnya
  • Mengidentifikasi peran HTTP, REST, dan JSON dalam pertukaran data
  • Menganalisis pemilihan metode HTTP untuk setiap operasi data
  • Menafsirkan status code respons server, baik sukses maupun gagal
  • Menerapkan fetch dengan header Content-Type dan serialisasi JSON
  • Merancang tiga state antarmuka: loading, error, dan empty state
  • Mengintegrasikan aplikasi dengan server backend/ bawaan buku
API (Application Programming Interface) — antarmuka pemrograman aplikasi: perantara antara aplikasi dan server.

Empat butir pertama adalah isi Kuis 2 (materi HTTP dan REST API, pertemuan 10) dan dipakai lagi di Bab 13 saat membaca token autentikasi; tiga butir terakhir adalah inti praktikum pertemuan 11: CRUD penuh dengan pengalaman pengguna yang jujur.

Peta halaman

  • Bagian 1 — Client–Server, HTTP, REST, dan JSON (subbab 10.1–10.2): data statis vs dinamis, dua program terpisah, trade-off satu sumber kebenaran, HTTP, REST, dan JSON.
  • Bagian 2 — Metode HTTP dan Status Code (subbab 10.3–10.4): pemetaan CRUD, aman dan idempoten, PUT vs PATCH, kelompok status code, dan membaca pertukaran HTTP.
  • Bagian 3 — fetch: GET, POST, PUT, DELETE (subbab 10.5): tiga langkah GET, tiga opsi POST, menghapus dengan respons kosong, kesalahan status 500, dan normalisasi respons.
  • Bagian 4 — Tiga State Antarmuka, Base URL, dan Struktur File (subbab 10.6–10.7): loading/error/empty, base URL, pemetaan endpoint, pemisahan api/ dan screens/, alur integrasi.
  • Bagian 5 — Studi Kasus dan Pengantar Autentikasi (subbab 10.7–10.8): tiga sistem tiga IPK, mitigasi titik kegagalan tunggal, dan token Bearer.
  • Praktikum: menghubungkan Aplikasi Manajemen Data Mahasiswa ke server backend/ — CRUD penuh, tiga state antarmuka, troubleshooting, dan kuis kilat.

Yang perlu diketahui sebelum membaca

Bab ini memakai alat yang sudah kamu punya: async/await dan JSON.stringify (Bab 3), ActivityIndicator dan FlatList (Bab 5), rute serta useFocusEffect (Bab 7), dan aplikasi Data Mahasiswa dari Bab 6–8. Tidak ada dependency baru yang perlu dipasang: fetch adalah fungsi bawaan JavaScript dan langsung tersedia di Expo.

Setiap kode di halaman-halaman berikut disalin verbatim dari slides/bab-10-rest-api-dan-backend-integration.md atau buku/bab-10-rest-api-dan-backend-integration.md; label sumber ada di kepala setiap blok kode. Perbandingan sebelum/sesudah menampilkan cara lama yang salah atau naif di samping cara yang benar; kode bertanda ilustrasi adalah ringkasan pola dari buku, bukan isi file sungguhan.

Pertanyaan penuntun

Konsep apa di bab ini yang paling sering diuji? Pemilihan metode HTTP dan pembacaan status code — keduanya bahasa bersama industri yang muncul di log server, di Project Akhir, dan lagi di Bab 13.
