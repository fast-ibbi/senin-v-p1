Membaca Data dengan GET: Tiga Langkah

fetch adalah fungsi bawaan JavaScript untuk mengirim permintaan HTTP. Karena React Native dibangun di atas JavaScript, fetch tersedia langsung di aplikasi Expo tanpa menginstal paket apa pun. Ia mengembalikan Promise, sehingga diproses dengan async/await yang sudah kamu pelajari di Bab 3.

Perhatikan tiga komentar bernomor di blok berikut: kirim permintaan, periksa status code, lalu urai JSON. Alamat endpoint disimpan pada satu konstanta API_URL supaya hanya perlu diubah di satu tempat.

response.ok bernilai benar hanya untuk status code 2xx, sehingga cara ini lebih baik daripada membandingkan response.status === 200 satu per satu. Terakhir, response.json() membaca body tanggapan sebagai teks lalu mengurainya menjadi objek atau array JavaScript.

Pertanyaan penuntun

Bila server menjawab 201 Created, apakah response.ok bernilai benar? (Jawaban: ya — ok mencakup seluruh kelompok 2xx, bukan hanya 200.)

Menambah Data dengan POST Butuh Tiga Opsi

Untuk mengirim data, fetch diberi opsi kedua. Tiga opsi itu berpasangan dengan tiga pertanyaan: method menjawab “operasi apa”, headers menjawab “isi pesan ini apa”, dan body membawa datanya.

Body HTTP hanya dapat berisi teks, bukan objek. Itulah sebabnya serialisasi dengan JSON.stringify wajib dipakai, dan header Content-Type: application/json memberi tahu server bahwa teks itu berformat JSON. Nilai yang dikembalikan adalah data mahasiswa yang baru tersimpan, kini disertai id dari server.

Mengubah Data dan Menghadapi 204

Pola PUT hampir sama dengan POST: metode ditukar, alamatnya ditambah id, body tetap hasil JSON.stringify. Bedanya satu hal kecil yang mudah terlewat — server boleh menjawab 204 No Content, yaitu sukses tanpa mengirim isi tanggapan. Memanggil response.json() pada tanggapan kosong justru melempar error.

Pengecekan response.status === 204 sebelum membaca body adalah bentuk kehati-hatian yang murah: bila server memilih mengirim data, data itu dipakai; bila tidak, fungsi mengembalikan data yang tadi dikirim. Pemanggil tidak perlu tahu bedanya.

Pertanyaan penuntun

Kalau server menjawab 204 untuk PUT, apa nilai balik yang paling masuk akal dari ubahMahasiswa? (Jawaban: data yang tadi dikirim — pemanggil sudah memilikinya, dan server menyatakan datanya tersimpan.)

Menghapus Data: Respons Sukses Bisa Kosong

DELETE hanya butuh satu opsi: metode. Sesudah sukses, banyak server menjawab 204 No Content — sukses tanpa body — sedangkan server lain menjawab 200 dengan pesan singkat. Kode yang membaca body tanpa memeriksa lebih dulu akan bekerja pada server kedua dan gagal pada server pertama.

Bila pemanggil hanya perlu tahu berhasil atau tidak, nilai balik boolean adalah pilihan yang tepat: ia tidak menjanjikan body yang belum tentu ada. Buku ini memilih jalan itu, dan layar daftar memakainya untuk langsung menghapus kartu dari state tanpa memuat ulang seluruh daftar.

Salah paham

“Sukses berarti ada respons untuk dibaca.” Tidak selalu. response.json() pada tanggapan 204 melempar error karena tidak ada teks untuk diurai, sehingga operasi yang sebenarnya berhasil dilaporkan gagal. Periksa status atau panjang body lebih dulu.

fetch Tidak Melempar Error saat Server Menjawab 500

Inilah kehalusan yang paling sering mengecoh pemula: fetch hanya melempar error untuk kegagalan jaringan — server mati, Wi-Fi putus. Status 4xx dan 5xx tetap dianggap permintaan yang “berhasil” oleh fetch, sehingga tanpa pemeriksaan tambahan, aplikasi akan memperlakukan pesan galat server sebagai data.

Karena itu pola if (!response.ok) throw adalah keharusan, bukan pelengkap. Kegagalan jaringan tetap muncul sebagai TypeError: Network request failed dan harus ditangkap dengan try/catch di pemanggil — bagian 4 menutup lingkaran itu dengan tiga keadaan antarmuka.

Pertanyaan penuntun

Aplikasi menampilkan daftar kosong padahal server menjawab 500. Di lapisan mana kesalahannya? (Jawaban: di aplikasi — respons galat tidak diperiksa, lalu isinya dipakai sebagai data; server memang salah, tetapi aplikasi seharusnya menampilkan keadaan galat.)

Menormalkan Bentuk Respons

Satu jebakan terakhir bersifat kontraktual, bukan sintaksis: sebagian server mengirim array langsung, sebagian membungkusnya pada properti data. Kode yang menganggap hanya satu bentuk akan menampilkan daftar kosong meski statusnya 200 — kasus yang sulit diduga karena semuanya tampak berhasil.

Baris Array.isArray(json) ? json : json.data menormalkan kedua bentuk menjadi array, sehingga layar tidak perlu tahu bentuk aslinya. Normalisasi kecil seperti ini membuat aplikasi tahan terhadap perbedaan antarserver tanpa mengubah satu baris pun di layar.

fetch atau Axios?

Axios memberi sintaks lebih ringkas, melempar error HTTP otomatis, dan punya interceptor untuk menyisipkan header token secara global. fetch adalah bawaan, lebih ringan, dan — karena “telanjang” — memaksa kamu memahami apa yang sebenarnya terjadi. Bab ini konsisten memakai fetch; Axios dapat kamu evaluasi setelah konsepnya kuasai.
