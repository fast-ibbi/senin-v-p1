Bagian 2 — Error Umum dan Debugging Jaringan

Enam pesan error React Native yang muncul berulang di semua project, penyebab tipikal, dan solusinya; lalu satu prinsip jaringan: uji endpoint sebelum menyalahkan aplikasi. Pesan error adalah penunjuk arah, bukan pengumuman kegagalan.

Subbab 14.2 · deck: “Enam Error React Native yang Paling Sering Muncul” · buku §14.2

Enam error React Native yang paling sering muncul

Error yang sama dapat muncul berulang pada semua project React Native. Mengenali pesan error sama pentingnya dengan mengenali sintaks bahasa: pesan itu adalah penunjuk arah, bukan sekadar pengumuman kegagalan. Empat error pertama menghentikan aplikasi (error fatal); dua terakhir muncul sebagai peringatan, tetapi tetap harus ditangani karena menandakan desain yang rawan bug.

Subbab 14.2 · deck: “Dua Error Fatal: Module dan Hook” · buku §14.2 · Error 1–2

Dua error fatal pertama: module dan hook

Pesan Unable to resolve module berarti modul yang kamu import tidak ditemukan oleh Metro (bundler React Native, alat yang menggabungkan semua berkas JavaScript menjadi satu bundel). Penyebabnya path salah, nama berkas salah ketik, atau — sering terjadi di Windows — perbedaan huruf kapital antara KartuMahasiswa.js dan kartumahasiswa.js.

Pesan Invalid hook call berarti sebuah hook dipanggil di tempat yang dilarang. Hook seperti useState dan useEffect hanya boleh dipanggil di tingkat atas fungsi komponen, tanpa syarat. Penyebab paling umum: memanggil hook di dalam percabangan if, di dalam callback event, atau di dalam fungsi biasa yang bukan komponen.

Penyebab dan solusi dua error fatal pertama · sumber: deck “Dua Error Fatal” & buku §14.2
ErrorPenyebab lazimSolusi
Unable to resolve module Path atau nama berkas salah; beda huruf besar-kecil; paket npm belum terpasang Perbaiki path; untuk paket npm jalankan npx expo install react-native-xyz, lalu tekan r
Invalid hook call Hook dipanggil di dalam if, callback, atau fungsi biasa Pindahkan pemanggilan hook ke level teratas komponen; hitung nilai bersyarat setelah hook dipanggil

Salah paham

Aturan emasnya satu kalimat: jangan pernah memanggil hook di dalam if, for, atau fungsi bersarang. Cabang yang menyelinap di antara dua hook terlihat wajar di mata pemula, tetapi melanggar aturan urutan hook — dan React menolaknya bukan karena gaya penulisan, melainkan karena ia kehilangan cara memasangkan state.

Pertanyaan penuntun

Kenapa React peduli di mana hook dipanggil? (Jawaban: React memasangkan state menurut urutan pemanggilan hook, dan urutan itu harus sama pada setiap render.)

Error ketiga: properti dibaca sebelum datanya tiba

Kamu mencoba membaca properti dari nilai yang belum ada — biasanya karena data belum dimuat dari API saat komponen pertama dirender. Ada dua penyebab tersembunyi yang mudah terlewat: salah menulis nama properti (nama versus name), dan respons API yang bentuknya tidak seperti dugaanmu. Bentuk respons yang dipakai buku ini adalah { data: [...] } (Bab 10).

Pola ini sudah kamu pakai di bagian 1: state ipk dimulai sebagai null dan layarnya menampilkan “memuat...” — pola yang justru mencegah error ini muncul.

Pertanyaan penuntun

Bagaimana kamu tahu struktur jawaban API sebelum menuliskannya? (Jawaban: dengan mencetak jawabannya sekali saat integrasi pertama — console.log sebelum dipetakan.)

Subbab 14.2 · deck: “Error Keempat dan Dua Peringatan yang Sering Diabaikan” · buku §14.2 · Error 4–6

Error keempat dan dua peringatan yang sering diabaikan

Error keempat adalah aturan Bab 5 yang terlupa: React Native tidak mengizinkan teks polos berada langsung di dalam View; seluruh teks harus dibungkus komponen <Text>. Peringatan kelima menandakan rancangan yang rapuh: FlatList di dalam ScrollView dengan arah gulir yang sama membuat React Native tidak dapat menghitung tinggi konten dengan benar, sehingga performa menurun dan perilaku gulir menjadi aneh. Peringatan keenam tidak menghentikan aplikasi, tetapi React bisa menggambar data yang salah atau kehilangan state baris saat datanya diperbarui.

Pertanyaan penuntun

Kenapa indeks array buruk sebagai key? (Jawaban: karena saat urutan data berubah, React kehilangan jejak baris mana yang berubah dan bisa menggambar data yang salah.)

Subbab 14.3 · deck: “Uji Endpoint Dulu Sebelum Menyalahkan Aplikasi” & “Server atau Aplikasi? Satu Perintah, Dua Kesimpulan” & “Alamat Berbeda untuk Tiap Target” · buku §14.3

Uji endpoint dulu sebelum menyalahkan aplikasi

Aplikasi yang memakai API (Bab 10) memiliki satu lagi sumber kesalahan: jaringan. Prinsip pertamanya satu kalimat — uji endpoint sebelum mengintegrasikannya ke aplikasi. Bila server backend buku sudah berjalan, kamu dapat memeriksa endpoint langsung dari browser, atau dari terminal dengan curl: program baris perintah yang mengirim permintaan HTTP dan mencetak respons mentahnya.

Satu perintah, dua kesimpulan berbeda. Jika curl berhasil tetapi aplikasi gagal, masalahnya di sisi aplikasi — kode, konfigurasi, atau alamat. Jika curl pun gagal, masalahnya di server: belum berjalan, port salah, atau error status 404/500. Syarat kesimpulan pertama harus disebut: endpoint berhasil tetapi aplikasi tetap gagal. Endpoint yang menjawab 200 sementara aplikasi berjalan normal bukan masalah sama sekali.

Pesan “Network request failed” paling sering berarti alamatnya salah untuk target itu, server mati, atau perangkat dan komputer berada di jaringan berbeda. Pola yang dianjurkan Bab 10 — try/catch, pemeriksaan response.ok, dan state loading/error/empty — sekaligus berfungsi sebagai alat debugging: letakkan console.warn pada blok catch dan pada cabang !response.ok agar setiap kegagalan meninggalkan jejak di terminal.

Salah paham

Alamat berbeda untuk tiap target sudah dibahas di Bab 10; di sini ia dipakai sebagai langkah pertama debugging jaringan, bukan materi baru. Bila aplikasi menampilkan “Network request failed”, jangan langsung membongkar kode: periksa alamat untuk target itu, lalu pastikan server berjalan.

Pertanyaan penuntun

curl berhasil tetapi aplikasi gagal — di mana masalahnya? (Jawaban: di sisi aplikasi: kode, konfigurasi, atau alamat yang dipakai aplikasi.)
