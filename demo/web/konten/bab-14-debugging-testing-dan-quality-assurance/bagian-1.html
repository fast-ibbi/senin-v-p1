Bagian 1 — Debugging: Console dan DevTools

Menelusuri masalah pada kode yang sudah ada, bukan menulis fitur baru. Bagian ini membedakan debugging, testing, dan QA; menunjukkan tiga jenis pesan console yang berguna; memasang log berlabel pada titik perubahan state; lalu membuka React Native DevTools dan React DevTools.

Subbab 14.1 · deck: “Tiga Kegiatan, Satu Tujuan: Kode yang Bisa Dipercaya” & “Bug yang Sampai ke Pengguna Lebih Mahal daripada yang Tertangkap Lebih Awal” · buku §Materi

Tiga kegiatan yang sering tertukar

Sebuah aplikasi yang “hanya berjalan” belum tentu aplikasi yang benar. Debugging adalah proses menemukan dan memperbaiki kesalahan (bug) pada kode. Testing adalah kegiatan memeriksa perilaku perangkat lunak secara terencana untuk menemukan kesalahan. Quality assurance (QA, jaminan kualitas) adalah proses sistematis yang memastikan produk memenuhi kebutuhan pengguna; QA tidak hanya mencari bug, tetapi mencegahnya sejak awal melalui standar, checklist, dan prosedur.

Mengapa ketiganya perlu? Semakin banyak fitur yang kamu tumpuk — navigasi di Bab 7, formulir di Bab 8, API di Bab 10, autentikasi di Bab 13 — semakin besar kemungkinan satu perubahan kecil merusak bagian lain yang tampaknya tidak berhubungan. Kondisi itu bernama regression (kemunduran kualitas). Tanpa cara menelusuri kesalahan dan menguji perilaku, tim pengembang menghabiskan waktunya menebak-nebak, dan aplikasi yang rusak di tangan pengguna jauh lebih mahal daripada bug yang tertangkap sebelum rilis.

Ada satu pertanyaan yang memisahkan ketiganya dengan rapi: siapa yang bekerja paling awal? Debugging paling akhir, testing di tengah, QA paling awal. Itulah sebabnya QA disebut jaminan, bukan reparasi.

Salah paham

QA bukan “tim lain”. Di proyek kecil — termasuk proyek kelompokmu — QA adalah sikap pengembangnya sendiri. Menunggu ada orang lain yang menguji berarti menyerahkan kegagalanmu kepada pengguna.

Pertanyaan penuntun

Menyusun checklist sebelum menulis kode termasuk kegiatan apa? (Jawaban: QA, karena ia mencegah dan bukan memperbaiki.)

Console: tiga jenis pesan, tiga kegunaan

Cara paling sederhana — dan sering kali paling efektif — untuk menelusuri kesalahan adalah mencetak nilai ke console. Di React Native, panggilan console.log dari kode aplikasi tampil pada terminal tempat npx expo start berjalan, dan juga pada React Native DevTools. Kebiasaan yang baik: beri label pada setiap baris log agar mudah ditemukan saat banyak pesan bercampur, dan gunakan jenis pesan yang sesuai dengan tingkat kepentingannya.

Tiga jenis pesan console · sumber: deck “Console: Tiga Jenis Pesan, Tiga Kegunaan” & buku §14.1
PemanggilanUntuk apaContoh di bab ini
console.logMelihat nilai variabel atau alur eksekusiMencetak jumlah data mahasiswa
console.warnNilai di luar dugaan; aplikasi tetap jalanMahasiswa dengan IPK di bawah 3.0
console.tableArray objek sebagai tabel berkolomDaftar mahasiswa: NIM, nama, prodi, IPK

console.log pertama memberi tahu berapa banyak data yang dimuat — inilah penggunaan paling dasar: memastikan data sampai di tempat yang kamu duga. console.log kedua memakai operator spread ... (Bab 3) untuk meneruskan semua IPK ke Math.max. Perhatikan console.warn: pesan peringatan tidak menghentikan program, tetapi tampil mencolok di terminal sehingga kamu sadar ada kondisi yang perlu diperhatikan. Terakhir, console.table menyusun ulang data menjadi tabel berkolom NIM, Nama, Prodi, dan IPK — jauh lebih mudah dibaca daripada lima baris objek polos.

Kebiasaan menambahkan label teks pada setiap log (“Jumlah data mahasiswa:”) adalah perbedaan utama antara log yang berguna dan log yang membingungkan. Berkas ini bisa dijalankan langsung dengan Node, tanpa emulator.

Pertanyaan penuntun

Apa gunanya mencetak jumlah data lebih dulu? (Jawaban: memastikan datanya benar-benar datang sebelum mencurigai bagian lain.)

Log berlabel menunjukkan kapan state berubah

Strategi men-debug state diringkas menjadi dua lapis. Lapis pertama: cetak log pada titik perubahan state — misalnya di dalam useEffect (Bab 4) yang berjalan setiap state berubah. Lapis kedua: bila log tidak cukup, misalnya karena state berbentuk objek besar, periksa pohon komponen dengan React DevTools. Keduanya saling melengkapi: log menjawab “kapan dan dalam urutan apa”, React DevTools menjawab “apa isinya sekarang”.

State ipk diawali null — inilah penyebab paling umum error “undefined is not an object” bila kita lupa menyediakan kondisi “belum ada data”. useEffect mencetak nilai ipk setiap kali berubah, sehingga terminal menunjukkan urutan: null, lalu 3.45. Cleanup clearTimeout mencegah pembaruan state setelah komponen dilepas.

Pertanyaan penuntun

Mengapa log di dalam useEffect lebih berguna daripada log di luar komponen? (Jawaban: karena ia berjalan setiap state berubah, sehingga urutan kejadiannya terlihat, bukan hanya nilai terakhir.)

React Native DevTools dan tiga tombol terminal

Selain console, React Native menyediakan React Native DevTools — antarmuka penganalisis berbasis DevTools Chrome yang terhubung ke aplikasi yang berjalan. Untuk membukanya: pastikan aplikasi berjalan, tekan m pada terminal Expo untuk membuka menu developer di aplikasi, lalu pilih opsi debugger sesuai versi SDK 57. Di dalamnya ada tab berisi sumber kode, breakpoint (titik henti: baris tempat eksekusi dijeda agar kamu dapat memeriksa nilai variabel), dan tab Network untuk memantau permintaan jaringan.

React DevTools adalah alat terpisah — khusus ekosistem React, bukan bagian dari DevTools Chrome. Ia menampilkan pohon komponen dan nilai state tiap komponen secara langsung, dan dapat dijalankan sendiri.

Perintah pertama menambahkan react-devtools sebagai dependency pengembangan (devDependency) — alat yang hanya dibutuhkan saat menulis kode, bukan saat aplikasi dirilis. Perintah kedua meluncurkan jendela React DevTools yang menampilkan pohon komponen aplikasimu secara real-time.

Salah paham

Kombinasi tombol bersifat sensitif versi, jadi jangan menghafalnya dari buku. Menu dan kombinasi tombol dapat berubah antarversi Expo; daftar yang dicetak terminal npx expo start adalah sumber kebenaran untuk versi yang kamu pakai. Bila m tidak merespons, fokuskan jendela terminal Expo lebih dulu, atau goyangkan emulator Android.

Pertanyaan penuntun

Apa analogi yang tepat untuk kedua lapisan itu? (Jawaban: log seperti rekaman kamera lalu lintas — ia menunjukkan urutan kejadian; React DevTools seperti foto kondisi sekarang — ia menunjukkan isi state saat ini.)
