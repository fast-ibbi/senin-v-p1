Praktikum Bab 15 — Build APK dan Laporan Build

Empat pekerjaan: melengkapi identitas aplikasi di app.json, memeriksanya sebelum dikirim ke cloud, membuat eas.json dengan tiga profil, dan memisahkan alamat backend ke .env. Hasil akhirnya satu APK hasil build dan satu berkas LAPORAN-BUILD.md. Tanpa akun EAS, jalur alternatifnya tetap melatih konsep yang sama.

Tujuan praktikum

Setelah menyelesaikan praktikum ini, kamu mampu:

  1. mengonfigurasi app.json proyek sendiri: identitas aplikasi, versi, ikon, dan splash;
  2. memverifikasi konfigurasi dengan npx expo config --type public sebelum build;
  3. membuat eas.json dengan tiga profil build: development, preview, dan production;
  4. menjalankan build Android lewat EAS, atau jalur alternatif ekspor bundel bila akun EAS belum dimiliki;
  5. menyusun laporan build yang memuat hasil, versi, dan catatan pengujian.

Kebutuhan

  • Node.js LTS 22 atau lebih baru (node --version).
  • Proyek hasil Bab 6–8, yaitu Aplikasi Manajemen Data Mahasiswa, atau proyek Expo lain yang sudah berjalan.
  • Folder assets/ berisi icon.png, adaptive-icon.png, dan splash-icon.png — biasanya sudah tersedia dari template; nama berkas bawaan template dapat berbeda antarsdk.
  • Koneksi internet stabil untuk build cloud dan unduhan hasil build.
  • Akun Expo gratis dan aplikasi Expo di ponsel — hanya untuk jalur build cloud.
  • Perangkat Android fisik untuk memasang APK hasil build.

Persiapan

  1. Duplikat proyek ke folder praktikum15; jangan bekerja pada proyek utama, karena build cloud mengunggah seluruh folder.
  2. Periksa node --version dan pastikan Node LTS 22 atau lebih baru.
  3. Siapkan ikon: PNG persegi 1024×1024 berisi gambar polos berwarna dan teks singkat sudah cukup. Simpan ke assets/icon.png, assets/adaptive-icon.png (dengan ruang kosong aman di tengah), dan assets/splash-icon.png.
  4. Baca app.json proyek dan catat nilai name, slug, dan version yang ada sekarang.

Langkah kerja

  1. Buka app.json dan lengkapi tujuh hal: name, slug tanpa spasi dan huruf besar, version mulai dari 1.0.0, android.package, ios.bundleIdentifier dengan application ID kebalikan domain, android.versionCode: 1, dan ios.buildNumber: "1". Bila proyek memakai Expo Router, pastikan plugins memuat "expo-router" dan scheme terisi.
  2. Periksa konfigurasi dengan npx expo config --type public, lalu periksa baris name, version, android.package, dan ios.bundleIdentifier pada hasilnya.
  3. Buat berkas eas.json di akar proyek dengan isi seperti blok Kode di bawah, lalu pastikan tiga profil ada.
  4. Siapkan environment variable: buat .env, lalu ubah layar yang memanggil API agar memakai process.env.EXPO_PUBLIC_API_URL dengan nilai cadangan yang sama. Mulai ulang npx expo start dan pastikan aplikasi tetap berjalan di emulator.
  5. Pasang alat EAS dengan npm install -g eas-cli, atau putuskan memakai npx eas-cli tanpa pemasangan. Pilih satu cara dan konsisten. Verifikasi dengan npx eas-cli --version.
  6. Jalur build cloud: npx eas-cli login, lalu npx eas-cli whoami untuk memastikan sesi aktif. Jalankan npx eas-cli build:configure dan periksa eas.json yang dihasilkan; biarkan bagian cli yang ditambahkannya tetap ada. Terakhir jalankan npx eas-cli build --platform android --profile preview dan tunggu sampai terminal menampilkan tautan serta kode QR.
  7. Jalur alternatif tanpa akun EAS: jalankan npx expo export --platform android. Perintah ini membuat bundel produksi dan asetnya di folder dist/ tanpa layanan cloud. Bundel ini bukan APK yang bisa diinstal; ia adalah latihan memahami apa yang dikemas EAS.
  8. Bila build cloud berhasil: unduh APK dari tautan, kirim ke perangkat Android, izinkan pemasangan dari sumber tidak dikenal bila diminta, lalu instal. Periksa nama aplikasi di bawah ikon, versi di pengaturan Android, dan fitur yang terhubung backend Bab 10.
  9. Tutup praktikum dengan LAPORAN-BUILD.md: tabel berisi tanggal, profil, platform, hasil, tautan atau ukuran berkas, dan catatan.

Penjelasan kode

app.json adalah identitas aplikasi. Kunci yang paling menentukan hasil build adalah slug (identitas proyek di ekosistem Expo — jangan diubah sembarangan setelah proyek pernah terdaftar), version (versi semantik yang dibaca manusia), serta android.package dan ios.bundleIdentifier (application ID — sekali dipublikasikan tidak boleh berubah). Praktikum ini memakai konfigurasi yang sama dengan contoh bab, hanya nilai identitasnya yang kamu sesuaikan.

Config plugin expo-splash-screen mengatur splash: imageWidth: 200 membuat gambar tidak memenuhi layar, resizeMode: "contain" menjamin gambar utuh, dan backgroundColor: "#1D4ED8" menyamakan warna latar splash dengan warna utama aplikasi sehingga transisi pembukaan terasa mulus. Jika proyek tidak memakai Expo Router, hapus "expo-router" dari plugins dan scheme dari app.json; router yang terpasang tetapi tidak dikonfigurasi akan membuat build gagal.

eas.json menentukan bagaimana tiap build dibuat. Profil development menghasilkan dev client yang dipasang di perangkat pengembang dan dipakai bersama npx expo start --dev-client. Profil preview menghasilkan APK rilis untuk pengujian: penguji memakainya seperti aplikasi sungguhan, lengkap dengan splash dan performa produksi, tanpa melewati toko aplikasi. Profil production menghasilkan AAB untuk toko dan menaikkan nomor versi mesin secara otomatis.

.env dan config/api.js memisahkan konfigurasi dari kode. Hanya variabel berawalan EXPO_PUBLIC_ yang disisipkan ke bundel; operator || memberi nilai cadangan bila berkas .env belum dibuat, dan API_URL diekspor agar layar lain mengimpor satu sumber alamat yang sama. Karena nilainya disisipkan saat bundel dibuat, hentikan lalu jalankan ulang npx expo start setiap kali .env berubah.

Hasil yang diharapkan

  1. Langkah 2: npx expo config --type public mencetak konfigurasi dengan name: "Aplikasi Mahasiswa" atau nama kamu, version: "1.0.0", serta android.package dan ios.bundleIdentifier sesuai yang kamu tulis. Bila nilainya berbeda dari harapan, konfigurasi belum tersimpan benar.
  2. Langkah 4: aplikasi tetap berjalan normal di emulator sesudah memakai environment variable; data mahasiswa dari backend tetap tampil, membuktikan EXPO_PUBLIC_API_URL tersisip dengan benar.
  3. Langkah 6 (jalur cloud): EAS menyelesaikan build dengan status finished, terminal menampilkan tautan, APK hasil unduhan terpasang di perangkat, nama aplikasi di peluncur sesuai name, dan splash biru muncul sesaat saat aplikasi dibuka.
  4. Langkah 7 (jalur alternatif): folder dist/ terisi bundel JavaScript produksi beserta asetnya, dan ukuran total bundel tercatat. Bandingkan dengan kesan “ringan” aplikasi saat dibuka, karena bundel produksi tidak lagi memuat alat debugging.
  5. Langkah 9: LAPORAN-BUILD.md terisi minimal satu baris per jalur yang dijalankan, dengan kolom tanggal, profil, platform, hasil, dan catatan.

Troubleshooting

Ketika build belum berhasil · sumber: buku §Troubleshooting
Gejala Penyebab Solusi
Setelah npm install -g eas-cli, perintah eas ditolak dengan “not recognized” atau “command not found” Folder pemasangan paket global belum terdaftar di PATH sesi terminal yang sedang berjalan Buka terminal baru; bila tetap gagal, pakai npx eas-cli ... untuk semua perintah
npx eas-cli login gagal dengan pesan jaringan, atau unggahan build berhenti Koneksi tidak stabil, jaringan kampus memblokir sebagian lalu lintas, atau sesi login kedaluwarsa Ulangi login, cek npx eas-cli whoami, coba jaringan lain; untuk unggahan yang gagal, jalankan ulang perintah build
Build cloud gagal dengan “Asset ./assets/icon.png does not exist” Path di app.json tidak cocok dengan berkas sungguhan — nama berbeda, folder tidak ada, atau beda huruf kapital karena server EAS peka huruf Samakan persis isi folder assets/ dengan path di app.json, lalu periksa dengan npx expo config --type public
Google Play menolak AAB dengan “Version code 1 has already been used” android.versionCode pada unggahan kedua sama dengan yang pertama, padahal Play mewajibkan nomor selalu naik Naikkan android.versionCode, atau aktifkan autoIncrement: true pada profil production
process.env.EXPO_PUBLIC_API_URL bernilai undefined, atau aplikasi memakai nilai lama setelah .env diubah Nama variabel tanpa awalan EXPO_PUBLIC_, berkas .env salah nama atau salah letak, atau server pengembangan belum dimuat ulang Periksa ejaan awalan, pastikan berkas bernama .env di akar proyek, lalu hentikan dan jalankan lagi npx expo start — bila perlu dengan -c untuk membersihkan cache

Salah paham

Kegagalan build bukan kegagalan logika aplikasi. Aplikasi yang sama berjalan sempurna di emulator, lalu gagal di server hanya karena satu huruf kapital pada path aset. Bacalah pesan errornya lebih dulu, periksa konfigurasi dengan npx expo config --type public, dan jangan membangun ulang berkali-kali tanpa memperbaiki penyebabnya.

Yang harus teramati

Untuk tiap baris laporan build, catat tiga hal:

  • Sumber build — profil mana yang dipakai, dan hasilnya APK atau AAB.
  • Identitas — version yang dipakai dan versionCode yang naik dibanding unggahan sebelumnya.
  • Bukti — tautan unduhan atau tangkapan layar dasbor, bukan nama profil saja.
Laporan yang baik menyebut bukti yang bisa diperiksa: “APK preview 1.0.0 (versionCode 1) terpasang di HP Redmi”, bukan “build sudah jalan”.

Kuis kilat

  1. Apa beda utama production build dan development build?
  2. Kenapa Google Play mewajibkan AAB untuk aplikasi baru?
  3. Variabel EXPO_PUBLIC_API_URL di dalam kode aplikasi sebenarnya bagaimana?
  4. Track Play tanpa peninjauan dan paling banyak 100 penguji adalah...
Kunci kuis kilat
  1. Production build diminifikasi, dioptimalkan, bertanda tangan, dan tanpa alat debugging; development build memudahkan iterasi dan debugging.
  2. Play merakit split APK per perangkat dari AAB, sehingga unduhan pengguna lebih kecil.
  3. Nilainya disisipkan ke bundel saat build, jadi tidak layak dipakai untuk secret.
  4. Internal testing: sampai 100 penguji, rilis cepat tanpa peninjauan.

Ringkasan bab

  1. Development build mengejar kecepatan iterasi; production build mengejar ukuran, kecepatan, dan keamanan — keduanya produk proses build yang sama dengan tujuan berbeda.
  2. EAS Build adalah build cloud Expo: eas login untuk autentikasi, eas build:configure untuk membuat eas.json, lalu eas build --platform android --profile <nama> untuk membangun.
  3. Tiga profil build: development untuk dev client, preview untuk APK pengujian internal, production untuk AAB toko dengan versi mesin yang naik otomatis.
  4. APK dapat diinstal langsung; AAB adalah format induk untuk Play yang disusun Google menjadi APK per perangkat — wajib untuk aplikasi baru sejak 2021.
  5. app.json memuat identitas aplikasi: name, slug, versi semantik, application ID kebalikan domain yang permanen, ikon 1024×1024 dengan adaptive icon, dan splash lewat plugin expo-splash-screen.
  6. Environment variable berawalan EXPO_PUBLIC_ disisipkan ke bundel saat build — praktis untuk alamat server, tetapi tidak pernah untuk secret.
  7. Signing membuktikan keaslian dan menjamin aplikasi hanya bisa diperbarui oleh pemilik kunci; keystore yang hilang berarti aplikasi tidak dapat diperbarui.
  8. Google Play mendistribusikan lewat empat track, dan Play App Signing memisahkan upload key dari kunci produksi.
  9. App Store melalui App Store Connect, TestFlight, dan App Review memerlukan keanggotaan Apple Developer berbayar tahunan.
  10. Tiga lingkungan memakai kode yang sama dengan konfigurasi berbeda — prinsip yang mencegah “berjalan di mesin saya”.
