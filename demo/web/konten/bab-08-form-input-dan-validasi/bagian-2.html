Satu Sumber Kebenaran, Tanpa Salinan Kedua

Controlled component adalah pola di mana nilai sebuah input sepenuhnya ditentukan oleh state React: value selalu berisi isi state, dan setiap ketikan hanya dapat mengubah state melalui onChangeText. Teks yang tampil dan state aplikasi selalu identik — tidak ada salinan kedua nilai di dalam komponen. State disebut sumber kebenaran tunggal.

Analogi yang dipakai di kelas: nilai input itu seperti saldo rekening — tidak ada buku catatan kedua yang boleh berbeda; apa yang tampil harus berasal dari satu sumber.

Mengapa React dan React Native memilih pola terkendali alih-alih membiarkan input mengelola nilainya sendiri? Sebab nilai input yang hidup di state dapat dibaca, divalidasi, diubah, dan direset oleh kode kapan saja — empat hal yang tidak mungkin dilakukan bila nilai hanya diketahui oleh TextInput internal.

Pertanyaan penuntun

Apa yang membuat mode edit mungkin pada sebuah formulir? (Jawaban: nilai formulir hidup di state, sehingga ia bisa diisi ulang secara programatik dari data lama.)

Satu Objek State, Satu handleChange untuk Tujuh Field

Formulir dengan banyak field menghadapi pertanyaan desain: menyimpan nilai setiap field dalam state terpisah, atau dalam satu objek state. Bab ini memilih objek tunggal. Seluruh nilai formulir hidup dalam satu objek form yang kunci-kuncinya persis menyamai nama field dan struktur data mahasiswa: { nim, nama, prodi, angkatan, ipk, email, telepon }.

handleChange memakai nama kunci terhitung dari Bab 3 sehingga satu fungsi melayani semua field: handleChange('nim', '2201001') memperbarui form.nim, handleChange('nama', 'Budi') memperbarui form.nama. Lebih sedikit kode diulang, dan aturan validasi cukup ditulis sekali per field.

Salah paham

...sebelumnya wajib ada. Tanpa penyebaran objek lama, semua field lain terhapus. Kesalahan ini tidak memunculkan pesan kesalahan di layar — nilainya hilang diam-diam, sehingga sulit dilacak saat menelusuri masalah.

Satu Objek Cepat Direset, tetapi Rapuh Kalau Lupa Menyebar

Pilihan objek tunggal bukan tanpa pertukaran, dan keputusan ini bukan benar-salah. Kelebihannya: reset formulir tinggal mengisi objek kembali; pengiriman ke server tinggal mengirim form sekaligus, dan itu dipakai di Bab 10; validasi berjalan terhadap satu objek utuh.

Kekurangannya: setiap ketikan harus menyebar objek lama, dan lupa menyebar berarti field lain ikut tertimpa. Untuk formulir berskala kecil sampai menengah, keterbacaan dan kemudahan reset mengalahkan kerumitan baris — keputusan yang mencerminkan praktik aplikasi produksi.

Pertanyaan penuntun

Kalau field hanya dua, apakah satu objek state tetap lebih baik? (Jawaban: untuk konsistensi pola, ya; batas pola ini baru terasa ketika formulir menjadi sangat besar.)

Apa yang Terjadi Jika…?

Tiga pertanyaan berikut biasanya memunculkan diskusi paling hidup di kelas. Coba jawab sendiri dulu sebelum membaca keterangan di bawah, lalu hubungkan dengan validasi di bagian 3.

  • handleChange menulis setForm({ [namaField]: nilai }) tanpa menyebar objek lama?
  • value diberi teks tetap, bukan dari state?
  • Pengguna menekan simpan sebelum menyentuh satu field pun?

Pertanyaan penuntun

Jawaban yang diharapkan: (1) enam field lain terhapus, hanya field yang diketik yang tersisa; (2) field menjadi hanya-baca — ketikan tidak muncul karena state tidak pernah berubah; (3) semua field melaporkan “Field ini wajib diisi” sekaligus karena validasi penuh berjalan saat submit.

State yang Bisa Diisi Ulang: Jalan Menuju Mode Edit

Keuntungan sumber kebenaran tunggal paling terasa pada satu kasus nyata: formulir mode edit harus bisa diisi ulang secara programatik dari data lama. Pada pola tak terkendali, isi field hanya diketahui TextInput sendiri, sehingga pengisian ulang harus memaksa komponen menggambar ulang dari awal.

Karena nilai formulir hidup di state, pengisian ulang cukup dilakukan sekali pada nilai awal: gabungkan objek kosong dengan dataAwal milik pemanggil. Validasi, reset, dan pengiriman tetap bekerja tanpa perubahan.

Salah paham

Mode edit bukan alasan meninggalkan pola terkendali, melainkan akibat langsung dari pola itu. Formulir yang harus diisi ulang secara programatik justru tidak mungkin memakai pola tak terkendali.
