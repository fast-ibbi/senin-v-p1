Subbab 4.5 · deck: “Serahkan Fungsi, Bukan Hasil Pemanggilannya” · buku §4.5

Serahkan Fungsi, Bukan Hasil Pemanggilannya

Inti subbab ini satu kalimat: yang diserahkan ke onPress (atau onClick di web) adalah fungsi itu sendiri, bukan hasil pemanggilannya. Menulis onPress={ubahTampilDetail()} membuat fungsi berjalan saat render, sehingga tombol terlihat tidak bekerja.

Handler di atas memakai functional update: setDetailTampil((tampilSebelumnya) => !tampilSebelumnya). Nilai baru dihitung dari nilai lama, jadi aman walaupun pembaruan terjadi beberapa kali dalam satu gelombang. Kalau handler perlu membawa data, pakai fungsi panah sebaris.

Pertanyaan penuntun

Bagaimana membawa data ke handler, misalnya nama program? (Jawaban: onPress={() => ubahKategoriProdi(prodi)}.)

Subbab 4.6 · deck: “Render Kondisional: Tiga Pola yang Cukup” · buku §4.6

Render Kondisional: Tiga Pola yang Cukup

Ketiga pola ini memakai ekspresi JavaScript yang mengembalikan nilai truthy/falsy (materi Bab 3 subbab 3.2) — bukan fitur baru milik React. Perhatikan contoh murah UI = f(state): satu state menggerakkan dua tampilan sekaligus — detailTampil menentukan teks tombol dan memunculkan blok detail pada saat yang sama.

Pilihan ketiga adalah mengembalikan null secara eksplisit dari dalam component — cara paling eksplisit untuk “jangan tampilkan apa pun”.

Salah paham

Hati-hati dengan && bila nilainya 0 atau string kosong: keduanya nilai falsy yang bisa tercetak di layar. Untuk kondisi seperti ini pakai ternary.

Subbab 4.6 · deck: “Render Daftar dengan map” · buku §4.6

Render Daftar dengan map

Render daftar dan component yang dipakai ulang adalah pasangan yang tidak terpisah: map menghasilkan component yang sama berulang kali, sekali untuk setiap anggota array.

Dua hal patut dicermati. Pertama, data tidak pernah dimutasi — map sudah mengembalikan array baru; mengubah datanya di dalam map justru melanggar aturan immutability. Kedua, key ditulis pada elemen yang dihasilkan map, bukan di dalam component KartuMahasiswa — ini kesalahan yang paling sering.

Pertanyaan penuntun

Kenapa data tidak boleh diubah di dalam map? (Jawaban: map sudah mengembalikan array baru; mengubah datanya justru melanggar immutability.)

Subbab 4.6 · deck: “key: Unik, Stabil, Bukan Indeks” · buku §4.6

key: Unik, Stabil, Bukan Indeks

Tekankan kata stabil: key bukan hanya unik, tetapi juga tidak berubah antar-render. Key adalah identitas yang dipakai React untuk mencocokkan elemen lama dan baru ketika daftar berubah. Praktik terbaik: pakai identitas data yang memang unik, seperti mahasiswa.id.

Salah paham

Key yang hilang tidak menghentikan aplikasi; peringatannya mudah diabaikan justru karena aplikasi tetap jalan. Masalahnya baru muncul belakangan dan sulit dilacak. Juga, jangan memakai key acak (Math.random()) sebagai jalan pintas — key-nya berubah di setiap render, sehingga React membuang lalu membangun ulang setiap elemen: lebih buruk daripada indeks.

Subbab 4.6 · deck: “Apa yang Terjadi Jika…?” & “Detail Menempel di Kartu yang Salah” · buku §4.6

Apa yang Terjadi Jika…?

Skenario ini diambil dari praktikum bab ini. Tuliskan dugaan jawabanmu sebelum membaca penjelasannya: daftar lima mahasiswa memakai key={index}, lalu kamu filter per program; satu kartu sedang terbuka detailnya, lalu daftar diurutkan ulang menurut nama. Apa yang terjadi?

Detail menempel di kartu yang salah. Indeks bergeser, React mencocokkan elemen lama dengan elemen yang salah, dan state detailTampil kartu lain ikut terbuka — datanya benar, tampilannya keliru. Gejalanya menipu: mahasiswa akan menyalahkan data yang tertukar, padahal yang keliru adalah pencocokan elemen oleh React. Perbaikannya: key={mahasiswa.id} — unik dan tidak berubah antar-render.

Pertanyaan penuntun

Kenapa React tidak membereskan masalah ini sendiri? (Jawaban: React tidak tahu identitas sebenarnya dari data; hanya pengembang yang tahu.)

Subbab 4.7 · deck: “Komposisi Component: Data Turun, State Tinggal” · buku §4.7

Komposisi Component: Data Turun, State Tinggal

Component composition adalah praktik menyusun component besar dari component-component kecil: App memuat DaftarMahasiswa, DaftarMahasiswa memuat beberapa KartuMahasiswa. Setiap component punya satu tanggung jawab yang jelas. Arah datanya: data mengalir turun, sedangkan state berdiri di tempat ia dideklarasikan — kalau tombol di kartu Budi ditekan, kartu Siti tidak ikut terbuka, karena detailTampil adalah state lokal di tiap kartu.

Pola children adalah cara kedua menyerahkan tampilan: component induk menyiapkan slot, pemakainya mengisi slot itu.

Salah paham

Jangan memecah component terlalu halus. Aturan praktis di bab ini hanya dua: pecah component ketika ia (a) dipakai ulang di lebih dari satu tempat, atau (b) mulai terlalu panjang untuk dipahami sekali lihat.

Subbab 4.8 · deck: “Dua Aturan Hook yang Tidak Boleh Dilanggar” · buku §4.8

Dua Aturan Hook yang Tidak Boleh Dilanggar

Hooks adalah jalan masuk ke fitur React dari component fungsi. Dua aturannya: hooks hanya dipanggil di dalam fungsi component (atau custom hook), dan selalu dipanggil di tingkat atas component — tidak di dalam percabangan (if), perulangan, atau fungsi bersarang.

Alasannya: React tidak menyimpan state berdasarkan nama variabel, melainkan berdasarkan urutan pemanggilan. Kalau urutannya bergeser karena pemanggilan berada di dalam percabangan, React membaca state yang salah. ESLint bawaan project Expo sudah memperingatkan saat aturan ini dilanggar, jadi kamu tidak perlu menghafalnya tanpa alat bantu.

Pertanyaan penuntun

Kenapa useEffect di dalam if berbahaya? (Jawaban: pada sebagian render efeknya dipanggil dan pada sebagian lain tidak, sehingga urutan hook bergeser.)

Subbab 4.5–4.7 · deck: “Satu Ketukan, Satu Re-render” · rangkuman buku §4.5–4.7

Satu Ketukan, Satu Re-render

Slide ini merangkum bagian tengah bab. Ceritakan ulang rantai ini dengan kalimatmu sendiri: tombol Tampilkan Detail ditekan → handler ubahTampilDetail berjalan → setter setDetailTampil((s) => !s) dipanggil → React menyimpan state baru → component dijalankan ulang (re-render) → render kondisional {detailTampil && …} menampilkan blok detail. Layar tidak bisa berubah tanpa setter, karena React hanya tahu state berubah kalau setter dipanggil.

Pertanyaan penuntun

Kenapa layar tidak bisa berubah tanpa setter? (Jawaban: perubahan langsung tidak terdeteksi React.)
