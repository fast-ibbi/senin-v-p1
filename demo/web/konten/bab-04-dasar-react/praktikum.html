Praktikum Bab 4 — Data Mahasiswa

Aplikasi kecil yang mempertemukan seluruh materi bab: filter program studi, kartu dengan detail yang bisa dibuka-tutup, status pemuatan yang disimulasikan, dan rata-rata IPK yang dihitung otomatis. Struktur folder minimal: App.js di akar project, lalu folder components berisi DaftarMahasiswa.js dan KartuMahasiswa.js.

Yang perlu diketahui sebelum membaca

Data statis DATA_MAHASISWA dan PILIHAN_PRODI diletakkan di luar component: keduanya tidak perlu dibuat ulang di setiap render. Dua jam pertama praktikum biasanya habis untuk kegagalan lingkungan, bukan logika — kalau aplikasi tidak mau jalan, periksa tabel troubleshooting di bawah sebelum menduga-duga soal logika.

Hasil yang diharapkan

  1. Selama kurang lebih 2 detik, layar hanya menampilkan judul “Data Mahasiswa” dan teks “Memuat data mahasiswa...”.
  2. Setelah itu muncul lima tombol kategori dengan latar biru pada tombol aktif, baris ringkasan “Menampilkan 5 mahasiswa · rata-rata IPK: 3.41”, dan lima kartu mahasiswa.
  3. Menekan “Tampilkan Detail” pada sebuah kartu menampilkan IPK, email, dan telepon mahasiswa tersebut; teks tombol berubah menjadi “Sembunyikan Detail”; kartu lain tidak terpengaruh.
  4. Menekan kategori “Sistem Informasi” menyaring daftar menjadi 2 mahasiswa; ringkasan berubah menjadi “Menampilkan 2 mahasiswa · rata-rata IPK: 3.20”.
  5. Menekan kategori “Rekayasa Perangkat Lunak” menampilkan 1 kartu (Dewi Lestari) dengan rata-rata IPK 3.61.

Salah paham

Jangan menambal peringatan dengan key acak atau mematikan peringatan ESLint — itu menyembunyikan gejalanya, bukan sebabnya. Pola yang benar: baca pesan error sebelum menduga.

Yang harus teramati

Tiga hal yang dinilai di praktikum ini — bukti yang bisa diperiksa, bukan kesan:

  • Component terpisah — KartuMahasiswa dipakai ulang untuk setiap baris daftar.
  • State lokal — detail tiap kartu terbuka sendiri, tidak mengganggu kartu lain.
  • key yang benar — pakai mahasiswa.id, bukan indeks urutan.
Bukti yang bisa diperiksa, bukan kesan: “detail kartu Budi tetap terbuka setelah daftar difilter” lebih kuat daripada “aplikasinya jalan”.

Kuis kilat

  1. Apa beda props dan state, dan mana yang memicu re-render?
  2. Kita menulis onClick={simpanData()}, apa yang terjadi saat aplikasi jalan?
  3. Kapan useEffect(() => {…}, []) berjalan, dan kapan cleanup-nya berjalan?
  4. Kapan useMemo benar-benar diperlukan?
Kunci kuis kilat
  1. Props hanya dibaca anak dan tidak boleh diubahnya; state diubah lewat setter — keduanya memicu re-render, bedanya siapa pemiliknya dan siapa yang boleh mengubahnya.
  2. onClick={simpanData()} memanggil fungsi saat render, bukan saat tombol ditekan — tombol terlihat mati.
  3. useEffect(fn, []) berjalan sekali saat mount; cleanup saat unmount atau sebelum efek jalan lagi.
  4. useMemo perlu saat perhitungan terukur mahal; useCallback saat fungsi dikirim ke anak berbalut React.memo.

Ringkasan bab

  1. React menganut pendekatan deklaratif: UI = f(state) — tampilan dihitung dari data, dan React memperbarui layar secara otomatis saat state berubah.
  2. Component adalah fungsi yang mengembalikan JSX; React modern memakai functional component.
  3. JSX: satu elemen akar, semua tag ditutup, atribut camelCase, ekspresi dalam {'{ }'}, komentar {'{/* */}'}.
  4. Props adalah data masuk yang read-only; nilai default dibuat dengan parameter fungsi.
  5. State adalah data internal yang diubah lewat setter, selalu secara immutable — salin dulu, jangan mutasi.
  6. Event handling menyerahkan referensi fungsi ke prop on*; hindari tanda kurung saat render.
  7. Conditional rendering memakai ternary, &&, atau null; list rendering memakai map dengan key unik dan stabil.
  8. Komposisi component (termasuk prop children) menghasilkan component reusable dengan tanggung jawab tunggal.
  9. useEffect menangani efek samping dengan tiga momen lifecycle dan wajib punya cleanup untuk sumber daya seperti timer.
  10. useMemo dan useCallback menyimpan hasil/fungsi agar tidak dihitung ulang; gunakan hanya ketika terukur perlu.

Pertanyaan penuntun

Pesan penutup deck: mulai sekarang, setiap masalah “data berubah tetapi tampilan tidak” punya daftar periksa sendiri — setter, immutability, dan key. Ketiga kata itu juga yang menyambungkan bab ini ke Bab 5, tempat component React Native (View, Text, FlatList) menggantikan elemen HTML.
