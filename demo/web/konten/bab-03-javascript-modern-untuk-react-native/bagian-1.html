Subbab 3.1 · deck: “React Hampir Selalu Memakai const, Ini Sebabnya” & “const Menjaga Alamat Objek, Bukan Isinya” · buku §3.1

Variabel: const dan let

Variabel adalah tempat menyimpan nilai di dalam program. JavaScript versi lama hanya mengenal var, yang bersifat function scope dan mudah menimbulkan bug karena nilainya dapat diubah di mana saja tanpa disadari. Sejak ES6 (2015) ada dua cara deklarasi yang lebih aman: const untuk nilai yang diisi sekali dan let untuk nilai yang memang berubah. Keduanya bersifat block scope: hanya berlaku di dalam pasangan kurung kurawal terdekat.

Mengapa perlu dua jenis deklarasi? Jawabannya disiplin. const memberi sinyal bahwa nilai tidak boleh diubah sepanjang hidupnya, sehingga kemungkinan salah ubah yang tidak disengaja menurun. let dipakai ketika nilai memang harus diperbarui, misalnya pencacah perulangan. Analoginya: const seperti tulisan tinta, let seperti tulisan pensil.

Baris-baris terakhir memperlihatkan sifat penting const terhadap objek: nilai properti seperti ipk boleh diubah, karena yang dijaga const hanyalah rujukan (alamat memori) objeknya. Pola ini muncul di React sebagai const [nilai, setNilai] = useState(0) pada Bab 4: variabel nilai tidak pernah diisi ulang langsung, melainkan diganti melalui fungsi setNilai.

Salah paham

Peringatan yang paling sering muncul: “const berarti datanya tidak bisa berubah sama sekali”. Yang dijaga const adalah alamat objek di memori, bukan nilai propertinya. Bila dijalankan, namaAplikasi = 'Nama Lain' memunculkan TypeError; tunjukkan langsung di editor supaya kamu melihat pesannya sendiri.

Pertanyaan penuntun

Mengapa React hampir selalu memakai const? (Jawaban: nilai state tidak diganti langsung, melainkan lewat fungsi pengubah dari useState di Bab 4.)

Enam Tipe Data dan Operator

JavaScript memiliki enam tipe data dasar yang perlu dikuasai: string (teks), number (angka, termasuk desimal), boolean (benar atau salah), undefined (belum terdefinisi), null (sengaja dikosongkan), dan object yang di dalamnya termasuk array dan fungsi. Operator typeof dipakai untuk memeriksa tipe sebuah nilai, tetapi jangan mengandalkannya sendirian: typeof [] dan typeof null sama-sama menghasilkan "object".

Pengertian tipe data bukan sekadar teori, karena tipe menentukan perilaku operator. "1" + 1 menghasilkan teks "11" (penggabungan), sedangkan "1" - 1 menghasilkan angka 0 (pengurangan). Perbedaan inilah yang membuat strict equality === wajib dipakai dibandingkan ==, karena == mengubah tipe otomatis dan sering menghasilkan perbandingan yang mengecoh.

Baris 0.1 + 0.2 === 0.3 yang mencetak false adalah kejutan klasik bagi pemula: komputer menyimpan bilangan desimal dalam biner sehingga hasilnya 0.30000000000000004. Implikasinya, dalam aplikasi keuangan jangan membandingkan hasil hitung desimal secara langsung dengan ===; bulatkan dengan toFixed() atau bandingkan dengan selisih yang sangat kecil.

Pertanyaan penuntun

Kalau sebuah properti yang tidak ada diakses, hasilnya error atau undefined? (Jawaban: undefined — dan nilai itu harus ditangani dengan hati-hati.)

?. dan ?? Menjaga Akses ke Data Kosong

Dua operator modern yang paling sering dipakai di React Native adalah optional chaining ?. yang mengamankan akses properti yang mungkin kosong, dan nullish coalescing ?? yang menyediakan nilai bawaan hanya ketika nilainya null atau undefined. Keduanya lahir untuk mengurangi pola if (objek && objek.profil) yang panjang.

Operator % (modulo) menghasilkan sisa pembagian — 10 % 3 adalah 1 — yang berguna misalnya untuk menentukan baris ganjil atau genap dalam tampilan daftar. Operator ternary ? : adalah cara paling ringkas menulis percabangan satu baris dan akan sering kamu lihat di kode React. Pada contoh terakhir, properti ipk tidak terdefinisi sehingga perbandingannya menghasilkan false: mengakses properti yang tidak ada tidak selalu error, tetapi nilainya undefined.

Pertanyaan penuntun

Apa bedanya ?? dan ||? (Jawaban: || juga menyala untuk 0 dan '', sedangkan ?? hanya untuk null dan undefined — sebabnya nilai nol tidak boleh hilang.)

Subbab 3.3 · deck: “Urutan Kondisi Menentukan Benar atau Salahnya Hasil” & “Hanya Enam Nilai yang Dianggap Salah” · buku §3.3

Percabangan dan Enam Nilai yang Dianggap Salah

Percabangan memungkinkan kode berjalan hanya ketika kondisi terpenuhi. Setiap kondisi dievaluasi sebagai truthy (dianggap benar) atau falsy (dianggap salah); yang tergolong falsy hanyalah false, 0, '', null, undefined, dan NaN. Semua nilai lain truthy — termasuk array kosong [] dan objek kosong {}.

Percabangan hadir dalam tiga gaya dengan tujuan berbeda: if/else untuk kondisi kompleks, ternary untuk memilih di antara dua nilai sederhana, dan switch untuk membandingkan satu nilai dengan banyak kasus. Rantai if/else if/else berhenti pada cabang pertama yang benar, sehingga urutannya menentukan hasil.

Kata kunci break di dalam switch menghentikan pengecekan agar eksekusi tidak jatuh ke kasus berikutnya. Cara kerja inilah yang membuat switch lebih cocok untuk banyak kemungkinan nilai dari satu variabel, misalnya kode hari atau status pesanan.

Salah paham

Salah paham paling mahal di bagian ini: “kosong berarti salah”. Padahal if ([]) selalu masuk cabang benar, dan if (daftarMahasiswa) juga selalu benar walaupun daftarnya kosong. Tulis syaratnya eksplisit: if (daftarMahasiswa.length > 0).

Subbab 3.3 · deck: “Tiga Bentuk Perulangan, Satu Cara Memilih” & “Tiga Jebakan yang Paling Sering Terjadi” · buku §3.3

Tiga Bentuk Perulangan, Satu Cara Memilih

JavaScript menyediakan for saat jumlah putaran sudah diketahui, while saat berhenti bergantung kondisi, dan for...of untuk menelusuri nilai setiap elemen array. for...of adalah pilihan paling aman dan paling terbaca untuk array: ia menghilangkan seluruh kelas kesalahan “di luar batas array”.

Blok for klasik terdiri dari tiga bagian — inisialisasi penghitung, kondisi berhenti, dan pembaruan penghitung — dan bagian-bagian inilah yang rawan salah tulis. Perulangan while cocok ketika jumlah putaran tidak diketahui sebelumnya, misalnya membatasi percobaan login; pola yang sama kembali di Bab 13. Pola for...of juga menjadi dasar pemahaman iterasi yang dipakai React untuk merender daftar komponen di Bab 4.

Salah paham

for (const nilai in daftarNilai) pada array tidak mencetak nilainya, melainkan indeksnya: 0, 1, 2, …. Perulangan yang ditulis for (let i = 1; i <= 5; i--) juga tidak pernah berhenti karena syaratnya selalu benar. Perulangan tanpa henti hanya membekukan terminal, tidak merusak komputer — ajarkan Ctrl+C supaya kamu tidak panik saat praktikum.

Pertanyaan penuntun

Untuk menelusuri array, mengapa for...of lebih dipilih daripada for (let i = 0; ...)? (Jawaban: tidak ada indeks yang perlu dijaga, sehingga tidak ada kesalahan batas bawah maupun batas atas.)

Fungsi dan Arrow Function

Fungsi adalah blok kode bernama yang dapat dipanggil berulang kali — unit dasar penataan logika aplikasi. JavaScript modern mengenal deklarasi fungsi klasik dan arrow function yang diperkenalkan ES6. Keduanya dapat dipakai untuk tujuan yang sama, tetapi arrow function lebih ringkas dan tidak memiliki this sendiri; di dalamnya this merujuk ke lingkup di luar fungsi tersebut.

Itulah alasan ekosistem React nyaris selalu memakai arrow function untuk penangan peristiwa: kita tidak ingin this berubah ketika fungsi dipanggil sebagai tanggapan atas sentuhan pengguna. Perbedaan praktis lainnya, arrow function dengan tubuh satu ekspresi mengembalikan nilai secara implisit, sedangkan deklarasi fungsi klasik diangkat (hoisting) sehingga dapat dipanggil sebelum baris deklarasinya.

Keempat fungsi di atas menunjukkan spektrum gaya penulisan. tentukanPredikat memakai pola early return: setiap cabang mengembalikan nilai dan mengakhiri fungsi, menghindari rantai else if yang bertingkat. jumlahkan memperlihatkan rest parameter: semua argumen masuk ke array angka lalu dijumlahkan dengan reduce. Pola “fungsi kecil yang melakukan satu hal dengan jelas” inilah fondasi pure function yang akan diuji di Bab 14.

Salah paham

Arrow function bukan sekadar “fungsi yang lebih pendek”. Yang membedakan adalah this yang menunjuk ke lingkup luar, dan itulah sebabnya React memakainya untuk penangan peristiwa. Salah paham ini biasanya baru terasa di Bab 4, ketika penangan sentuhan mengakses nilai yang tidak seharusnya.

Pertanyaan penuntun

Apa yang terjadi bila tentukanPredikat() dipanggil tanpa argumen? (Jawaban: parameter default ipk = 0 dipakai, sehingga hasilnya 'Memuaskan' dan bukan error.)
