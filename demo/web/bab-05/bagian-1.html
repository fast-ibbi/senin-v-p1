Bagian 1 — React untuk Web dan React Native

Setiap kode disertai hasil yang diharapkan, dan setiap angka di halaman ini ditelusuri ke slides/bab-05-dasar-react-native.md, buku/bab-05-dasar-react-native.md, atau praktikum/bab-05-*.md.

Yang perlu diketahui sebelum membaca

Panel bertanda React Native adalah tiruan HTML/CSS, bukan React Native sungguhan: tidak ada kode React Native yang dijalankan di halaman ini. Tiruan itu meniru lima aturan yang paling mudah dibuktikan — flexDirection bawaan column (CSS: row), alignItems bawaan stretch, flexShrink bawaan 0 (CSS: 1), box-sizing: border-box di semua komponen, dan tidak ada margin collapse. Di perangkat asli hasilnya bisa sedikit berbeda karena font perangkat dan pembulatan piksel.

Panel bertanda React Web bukan tiruan: browser benar-benar merender HTML dengan aturan CSS yang ditampilkan, sehingga kolom kiri bisa dipakai sebagai pembanding yang jujur.

Subbab 1.1 · deck: “Konsepnya Sama, Medianya Berbeda” · buku §5.1

Konsepnya Sama, Medianya Berbeda

  • React: pustaka JavaScript untuk membangun antarmuka pengguna.
  • React Native: untuk membangun aplikasi mobile.
  • Konsep yang sama: component, props, state, dan hooks.

React lahir pada 2013 sebagai pustaka antarmuka web: komponen ditulis dengan JSX, lalu react-dom merendernya menjadi elemen DOM. Ketika React Native diluncurkan pada 2015, idenya tidak berubah — komponen, props, state, dan hook tetap sama persis — tetapi target rendernya diganti: alih-alih DOM, React Native merender komponen native, yaitu UIView di iOS dan ViewGroup di Android. Inilah inti “mengapa teknologi ini ada”: satu bahasa, satu cara berpikir, dua platform sekaligus.

Imbalannya adalah lapisan abstraksi. Fitur spesifik platform kadang memerlukan modul native tambahan, dan perilaku visual tidak pernah sepenuhnya identik antarponsel. Perbedaan praktis yang paling terasa saat menulis kode dirangkum pada tabel berikut (buku §5.1).

Lihat jawaban

Mediumnya: dari halaman web menjadi aplikasi mobile, sehingga elemen yang dirender dan cara menata gayanya ikut berganti.

Padanan ini tidak selalu satu-satu. Satu div di web bisa menjadi dua View sekaligus di React Native, tergantung kebutuhan layout — misalnya satu View untuk latar dan satu lagi untuk isi yang diberi jarak. Yang perlu dipegang adalah perannya: wadah, teks, gambar, area sentuh, dan gaya.

Contoh di bawah memakai komponen yang sama dari dua sisi. Kolom kiri adalah komponen React web (praktikum Soal 1), kolom kanan adalah versi React Native-nya (kunci Soal 1). Keduanya menampilkan kartu profil yang sama; yang berganti hanya elemen dan cara menata gayanya.

Pertanyaan penuntun

“Kenapa CSS tidak bisa dipakai apa adanya?”

Lihat jawaban

Karena tidak ada browser yang mem-parse CSS di aplikasi React Native. Gaya ditulis sebagai objek JavaScript melalui StyleSheet, tanpa selektor dan tanpa pewarisan.

Salah paham

Mencari berkas CSS di dalam project Expo, lalu menyimpulkan setup-nya rusak. Tidak ada berkas CSS di sana karena seluruh gaya tinggal di dalam berkas JavaScript.

Subbab 1.3 · deck: “HTML Dirender Browser, Komponen Dirender Native” · buku §5.1

HTML Dirender Browser, Komponen Dirender Native

  • Rendering elemen HTML pada browser.
  • Rendering komponen menjadi antarmuka native pada perangkat mobile.
  • Lingkungan eksekusi, akses fitur perangkat, dan dukungan platform ikut berbeda.

Bayangkan dua jalur dari satu sumber. JSX yang sama ditulis sekali; satu jalur berakhir di DOM browser, jalur lain berakhir di komponen native. Analogi yang dipakai di kelas: resep yang sama dimasak di dua dapur berbeda — bahannya sama, alat masaknya tidak, jadi hasil dan waktu memasaknya pun berbeda.

JSX → react-dom → DOM browser

Jalur React Web — berjalan di dalam browser, memakai API browser.

JSX → komponen native → UIView (iOS) · ViewGroup (Android)

Jalur React Native — berjalan di dalam aplikasi, tanpa browser di antaranya.

Akibat yang paling sering menggigit pemula: di React Native tidak ada browser, sehingga document, window, dan localStorage tidak tersedia. Kode yang memanggilnya tidak “berfungsi sebagian” — kode itu gagal. Penggantinya disediakan bab lain: data dari server di Bab 10, penyimpanan lokal perangkat di Bab 11, fitur perangkat di Bab 12.

Salah paham

Menganggap aplikasi React Native berjalan di dalam browser tersembunyi.

Pertanyaan penuntun

“Kenapa aplikasi React Native bisa mengakses kamera, sedangkan halaman web tidak selalu bisa?”

Lihat jawaban

Karena kodenya berjalan di dalam aplikasi native, bukan di dalam kotak pasir browser. Izin dan kemampuannya mengikuti sistem operasi perangkat, bukan aturan tab peramban.

Subbab 1.4 · deck: “Bagian Kode yang Bisa Dipakai Ulang”

Bagian Kode yang Bisa Dipakai Ulang

  • Logika component, props, dan state bisa dipakai ulang.
  • Yang berganti: elemen yang dirender dan cara menata gayanya.
  • Kapan memakai React Web, kapan memakai React Native.

Hasil yang diharapkan390 px

Judul Halaman
Deskripsi singkat halaman.
Tekan

Ketiga baris itu tampil sama besar dan saling menempel — dan itu memang hasil yang benar. Kode di atas tidak menulis satu pun style, jadi berlaku ukuran teks bawaan 14 pt tanpa jarak. Pressable juga tidak menambahkan bentuk tombol apa pun: berbeda dari Button, Pressable hanya menyediakan area sentuh, dan tampilannya sepenuhnya bergantung pada gaya yang kita tulis (dibahas di Bagian 3).

Aturan praktis memilih: React Web untuk halaman yang dibuka lewat tautan dan mudah diperbarui; React Native untuk aplikasi yang butuh fitur perangkat, notifikasi, dan kehadiran di layar utama ponsel. Peringatan kecil untuk kode di atas: onPress sengaja berisi fungsi kosong — di praktikum nanti isi dengan aksi nyata.

Pertanyaan penuntun

“Bagian mana yang kamu salin apa adanya dari project web?”

Lihat jawaban

Fungsi komponen, state, dan hooks — bukan elemen dan gayanya. Struktur JSX, logika, dan penamaan state tetap sama persis.

Praktikum 1 · deck: “Praktikum 1: Halaman Sederhana di Dua Platform”

Praktikum 1 — Halaman Sederhana di Dua Platform

  • Satu halaman berisi judul, deskripsi, dan tombol.
  • Kerjakan dua kali: React Web, lalu React Native.
  • Bandingkan bagian kode yang sama dan yang berganti.

Yang dinilai bukan hasil visualnya, melainkan catatan perbandingan: baris mana yang identik dan baris mana yang berganti. Pertanyaan penuntunnya: “Berapa baris yang benar-benar berubah?” — jawabannya biasanya hanya import, nama komponen, dan definisi gaya. Waktu yang disediakan di lab sekitar 25 menit.
